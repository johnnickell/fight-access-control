# WF-040: Fight Common Domain helpers

## Question

Which existing production calls can use released Common helpers without changing behavior or caller types?

## Findings

- The minimum in [Composer](../../../composer.json) is v1.5.1 (`^1.5.1`). The locally available [release-tagged helper source](https://github.com/johnnickell/fight-common/blob/v1.5.1/src/Domain/functions.php) matched the installed file byte-for-byte; the tag resolves to the commit listed in the local lock. [Common's Composer config at that tag](https://github.com/johnnickell/fight-common/blob/v1.5.1/composer.json) loads the file through `autoload.files`. No dependency bump or separate include is needed.
- **First pass: `email()` in 12 production locations.** Its signature is `email(string $address): EmailAddress`; it directly returns `EmailAddress::fromString($address)` without changing input or catching exceptions. The 11 Domain sites cover [User commands](../../../src/Domain/AccessControl/User/Command) and [events](../../../src/Domain/AccessControl/User/Event), [email-change command](../../../src/Domain/AccessControl/EmailChangeGrant/Command/RequestEmailChange.php) and [event](../../../src/Domain/AccessControl/EmailChangeGrant/Event/EmailChangeRequested.php), and [password reset](../../../src/Domain/AccessControl/PasswordResetGrant/Command/RequestPasswordReset.php). The one Application site is [UserAuthentication](../../../src/Application/AccessControl/User/Authentication/UserAuthentication.php); keep its existing error handling and evaluation order. Retain class imports still used in declarations.
- **Keep typed collections.** The v1.5.1 helpers return `ArrayList<mixed>`, `HashSet<mixed>`, and corresponding broad queue, stack and table types. A class-string argument still constrains the runtime collection but does not preserve caller inference. Retain typed construction in [ListUsersHandler](../../../src/Application/AccessControl/User/QueryHandler/ListUsersHandler.php) and [User](../../../src/Domain/AccessControl/User/User.php) rather than adding casts or annotations to force a substitution.
- **Keep identifier and serialization semantics.** The `uuid()` helper generates a COMB UUID, not the random UUID used by [RoleRevision](../../../src/Domain/AccessControl/Role/RoleRevision.php) or the parsed UUID used by [AuditEvidenceId](../../../src/Domain/AccessControl/Audit/AuditEvidenceId.php). It does not replace AccessControl-specific identity constructors. `json_data()` returns a `JsonObject`, not the string returned by callers such as [AgentOperationScope](../../../src/Domain/AccessControl/AgentCredentialOperation/AgentOperationScope.php). No direct Common string, URI, URL or `JsonObject` factory calls were found in the production sweep.

## Planning handoff

Prefer explicit `use function Fight\Common\Domain\…` imports for equivalent helpers, with the lasting rule in the [local PHP standard](../../../docs/engineering/standards/PHP.md). Limit the first migration to the identified production email calls. Do not rewrite tests, add a blanket sniff, or add project-local helper copies. Retain normalization, exception handling, types and evaluation order. Verify on the minimum supported version and through ordinary static analysis, applicable type-contract checks and the canonical gate, with focused coverage of hydration and authentication failure behavior. This is a source comparison, not a runtime or build result.
