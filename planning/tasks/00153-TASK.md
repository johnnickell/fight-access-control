## Contracts and Boundaries

- Give each handler an optional last nullable AuditEvidenceRepository. Omitted/null deliberately disables durable
  audit; configured failure cannot downgrade to disabled/no-op storage. Reuse existing required UserId actor input,
  preserving current round trips; no new nullable actor, label parsing, ambient lookup or System/Anonymous fallback.
- With auditing enabled, validate needed attribution before the first mutation requiring evidence. Discovery and
  validated no-change need no newly introduced audit-only actor obligation; existing required actors stay required
  even when disabled. Attribution grants no authority: administrative entry/target/scope policy remains consumer-owned
  under ADR 0010, with package custom/managed/reserved identity and name rules intact.
- Explicitly add evidence after authoritative validation/persistence and before the same actual transaction commits.
  Capture direct typed actor, Role subject, unique evidence identity, trusted outcome time and actual message
  correlation. Include the complete authoritative RoleRevision/incarnation: creation has no fabricated predecessor,
  rename carries actual before/after, removal has no fabricated successor. Evidence IDs are not command deduplication.
- Preserve caller expected revision, ABA/same-ID recreation rejection, name uniqueness, complete-state CAS and removal
  User/reference fences, including registration races. A same-name rename retains revision/current-state validation
  without write, timestamp advance, success fact or mutation evidence. Do not replace stale caller intent with a
  newly read revision or turn generic failures into not-found/no-change.
- Audit failure/concurrent loss rolls back staged Role/evidence together. Preserve primary throwable, uncertain commit
  and ordinary post-commit publisher/subscriber failure: committed evidence survives publication failure, which does
  not imply rollback. No rejected-attempt store, replay/outbox or Agent issuance warning-return exception is added.
- Use bounded action-specific typed/validated facts, not entities, raw messages, credentials, hashes/ciphertext,
  exception diagnostics or unnecessary personal data. Free text needs explicit safety admission; typed evidence is
  not automatically authorized public API/log output. Never manufacture evidence by inspecting a returned Event,
  wrapping the UoW or intercepting repository writes. Existing success facts follow confirmed commit only.
