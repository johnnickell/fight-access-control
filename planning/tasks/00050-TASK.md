# Revoke Agent credentials and fence pending delivery

## What to Build

Deliver atomic Agent revocation and predecessor-delivery cancellation through every retained lifecycle write boundary,
including direct non-HTTP calls. Supply the public cancellation/fencing capability consumed by replacement rotation,
without building another rotation workflow. This is slice A of the five-TASK split John approved on 2026-09-27 under
[TICKET-00013](../tickets/00013-TICKET.md), targeting [EPIC-00009](../epics/00009-EPIC.md)'s `v0.5.0`.

Build on [TASK-00046](00046-TASK.md)'s committed operation/delivery and authority contracts. Domain owns retirement
invariants and repository write obligations; Application owns the package transaction, audit and event ordering.
Consumers implement persistence and authorization participation on the same connection. No production Adapter layer.

## Use Case and Contract

- **Actor/trigger:** a currently authorized maintainer revokes an Agent, or a retained lifecycle writer retires an
  expected predecessor. Trusted caller policy remains consumer-owned; actor strings are audit data, not authority.
- **Input/validation:** exact Agent and expected authority, original delivery binding and current authoritative state.
  Missing/stale authority rejects; terminal revocation cannot revive. Every retained write shares the same authority,
  credential, destination and delivery fences used by admission, including no bypass through repository replacement.
- **Effects:** one package-owned Unit of Work commits Agent retirement, cancellation/fencing of predecessor work,
  retirement of its delivery copy and safe audit. Cancellation invalidates pending/claimed/admitted work without
  decrypting or invoking a sink. It cannot recall bytes from an already admitted external call.
- **Result/events:** safe lifecycle outcome and existing post-commit revocation fact/failure behavior. Do not extend
  the provision/rotation publication-warning exception to revocation. No new Query or consumer activation event is
  needed; original operation identity remains unchanged and its disposition becomes retired.

## Acceptance Criteria

- [ ] Inventory and cover all current public/direct lifecycle writers, including `AgentCredentialLifecycleService`
      and `AgentRepository::replace`. Record the supported shared cancellation/write contract and expected-state
      transitions for pending, claimed, admitted and retired delivery. Unsupported transactional participation fails
      closed; no outer/nested transaction, event subscriber or consumer lifecycle-policy replica substitutes.
- [ ] Revocation atomically retires credential authority, cancels delivery, removes its recoverable copy and records
      audit. Rotation-capable repository writes use the same cancellation fence. A persistence/audit/cancellation fault
      rolls back the whole mutation; no partial credential retirement or separately committed cancellation survives.
- [ ] No key, decryption or sink availability is needed to revoke/cancel. Preserve one active credential, terminal
      revocation, authentication's nonce/current-authority fence and existing revocation publication semantics.
- [ ] Behavioral repository/service tests interleave retirement with controlled claim/admission/outcome state writes:
      pre-admission retirement denies admission; stale completion loses; admitted state cannot be revived. Revoke/regrant
      of caller or destination authority cannot validate an old epoch. Consumer authority writers must share these fences.
- [ ] Cancellation preserves safe original operation/credential identity, canonical binding and replay evidence. It
      cannot substitute a successor secret or reset slot order. No secret/ciphertext/provider detail leaks into audit,
      events, results, serialization, debug or failures; the authentication envelope is not a recovery fallback.
- [ ] Define retirement/retention relationships with TASK-00046's finite defaults and optional validated overrides.
      Cancellation is not blocked by new-work capacity and requires no additional human approval or manual limit setup.
- [ ] Keep focused rollback, fencing and revocation tests here. These state-interleaving tests are not proof of a real
      sink invocation: TASK-00051 tests admission/delivery, TASK-00048 integrates replacement rotation, and TASK-00054
      proves all retained paths against those real package workflows. Map this slice to TICKET-00013 D2/D5/D6/D7.
- [ ] Update public repository/composition and lifecycle guidance, including direct consumer writer obligations.
      No legacy raw-return escape path may survive the completed replacement; TASK-00048 owns replacing/rejecting the
      old rotation API, not a second implementation in this TASK. Intermediate work is not released/adopted.
