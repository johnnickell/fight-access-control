## What to Build

Deliver the protected messages/detail journey in [TICKET-00029](../tickets/00029-TICKET.md): actual Agent Permission
checks combined with trusted consumer structural scope and separate metadata/body grants through Common's
`DetailReadAdmission`/`DetailAccess`, `ListCapturedMessages` and `GetCapturedDetail`. Use the existing owning Common
handlers/readers and TASK-00084's protected Tool binding for `execution.messages` and `execution.detail`.

Define reusable inward Permission-gate/delegation tooling for actual Common admission ports while consumers own
project/session/phase/activity/detail relationships, sharing and target scope. A supplied selector or Tool allow
must never become an unrestricted grant. Metadata admission is independent of timeline admission; body admission
is separately required and cannot bypass metadata or structural scope. Explicitly admitted protected detail can
work even when timeline access is absent. Consequently [TASK-00089](00089-TASK.md) is not a dependency.

Common owns protected selection/Query logic, absence/concealment, capture/retention projections, chunk/message-page
bounds and bytes. Preserve Domain/Application ownership and inward public dependencies; no Common Adapter import
into production Application logic, AccessControl persistence adapter, alternate reader, copied SQL or content
retrieval implementation. Actual consumer scope policy remains outside the package.

## Acceptance Criteria

- [ ] **Real independent composition:** Real AccessControl authority checks and trusted consumer scope compose with
  Common's actual Tool → Query → handler/reader path, plus direct owning Query paths. Define the useful reusable
  helper without a relationship store or duplicate business logic. No grant from request selectors, `_meta`, supplied
  Permission arrays, role labels, a discovered reference or coarse Tool availability.
- [ ] **Metadata/body matrix:** Capability-allowed/data-denied, metadata-only, body-only, fully permitted and
  independently admitted detail cases have distinct truthful outcomes. Body-only authority cannot bypass required
  metadata/structural admission. Metadata-only access discloses no body. Allowed detail succeeds despite denied
  timeline access; timeline permission/reference disclosure never grants protected metadata or bodies.
- [ ] **Complete relationship isolation:** Forged project/session/phase/producer/activity/detail/kind combinations,
  cross-project/session references and mismatched identities retain actual Common safe concealment/nullable
  outcomes. Rows, message totals, protected references and producer/relationship metadata reflect permitted scope,
  not a global read/count followed by presentation-only filtering. Direct Query paths cannot bypass admission.
- [ ] **Fresh pages and chunks:** Re-evaluate applicable current Permission/consumer scope for each later request,
  message page or chunk without replaying the authenticated nonce per decision. Revocation/rotation/Permission or
  relationship changes affect later requests, while ordinary request snapshots keep their documented semantics.
  Historical references, a previous page/chunk or captured bytes grant no subsequent access. TASK-00088/live
  transport is not required for these ordinary requests; actual repeated background/live work uses it separately.
- [ ] **Denied body read measured:** Instrument protected read/opening boundaries and show forbidden bodies are not
  retrieved/disclosed. Permitted text/binary chunks, message pages and exact complete encoded output preserve Common
  limits and projections, including empty bytes versus unavailable data, metadata-only results, missing/concealed
  records, disappearance/retention and partial/complete capture markers. Do not invent complete capture or continued
  storage guarantees. No body sentinel or encoded body appears in safe timelines/errors/diagnostics.
- [ ] **Safe truthful faults and effects:** Invalid selection/ranges and storage/policy/resolution faults retain
  Common's supported protocol-safe behavior, not raw exception text, fabricated empty success or an alternate
  redacted successful schema. Assert unchanged business state/events/Commands and current direct authority; a mere
  stub Boolean or call-order check is not the integration outcome.
- [ ] **Qualified minimum and guidance:** Establish implemented/independently accepted/qualified, tagged Common
  execution Tool/detail admission/reader APIs and the first sufficient supported minimum; record exact version/
  source/lock evidence and test that minimum. No guessed version or dev snapshot as stable. Document separate
  scope/metadata/body versus timeline authority, direct paths, freshness, actual Common bounds/capture/absence and
  remaining consumer lifetime/race/storage qualification; update affected guidance and `CONTEXT.md`.
- [ ] **Complete gates and independent acceptance:** Focused real handler/reader composition with actual AccessControl
  authority and controlled scope/persistence proves allow/deny/fault, grant combinations, relationships, totals,
  changed access and read/open counts. Exact owned statement coverage/full canonical package gate pass with complete
  log/actual exit/receipt; independent Review and behavioral QA accept the subject. Package fixtures are not actual
  deployed persistence, consumer relationship policy, transport or concurrency qualification.
