# Make AgentName own provisioning and rename semantics

## What to Build

Deliver the name-ownership slice of [TICKET-00036](../tickets/00036-TICKET.md). Make AgentName own one normalization
and validation algorithm, preserving existing provisioning canonical bytes and intentionally bringing rename into
alignment. Normally one bounded Domain/Application/adapter/test/docs PR with a documented pre-v1 rename change.

### Actors, Messages and Effects

Authorized provisioning and UpdateAgent/profile rename use the same normalized AgentName. Existing operation
requests, UpdateAgent, AgentNameChanged and profile/status outputs retain their identities/shapes. A real rename
changes only name/update time and publishes after commit; a valid no-op does neither. Consumer authorization,
current Agent fences and retained provisioning correlation remain independent of name construction.

### Accepted Rule and Caller Contract

Use the existing provisioning rule: trim the fixed Unicode White_Space edge set plus NUL, require nonempty UTF-8
and at most 120 code points, preserve case/internal whitespace and perform no NFC conversion. Preserve treatment
of U+200B/U+FEFF and the exact fixed set from the current canonicalization contract, not a changing Unicode property.
AgentName::fromString owns it; canonical request construction consumes the value rather than defining another name
algorithm. Translate failures at the existing operation/Tool boundaries without exposing private diagnostics.

Before: provisioning uses AgentOperationCanonicalization::name while rename uses PHP trim through AgentName.
After: both consume AgentName and canonicalization serializes that owned value. No public helper alias or configurable
normalization/version mode remains solely for earlier iterations.

  Unreleased notes aligned and no legacy mode, normalization flags or compatibility helper.

  independent Review/applicable QA cover this bounded semantic change without claiming consumer migration.
