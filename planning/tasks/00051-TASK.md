## Use Case and Contract

- **Actor/trigger:** a worker authenticates as itself with current explicit delegation to the original scope and
  dispatches one exact delivery. IDs or a claimed actor string alone do not authorize discovery, claim or delivery.
- **Claim:** commit a monotonic attempt fence, opaque token and bounded lease. Claim reserves work; it grants no
  decryption permission. Preserve globally unique delivery ID, original bytes and destination write reservation.
- **Admission:** immediately before materialization, a short package-owned transaction reads authoritative state and
  trusted time, checks current caller/delegation, scope, destination owner/binding/order, exact active credential,
  pending state, claim and retention. Consumer authorization participates on the same connection and holds fences
  through commit without its own begin/commit. Commit linearizes permission; persist authorizing epochs/revisions and
  the earliest claim/authorization/delivery deadline. Recheck that deadline after commit and before decrypt and invoke.
- **Invocation:** only confirmed valid admission permits a short-lived non-serializable invocation to the bound
  server-registered slot, outside all transactions. No arbitrary URL/path, general secret handle or raw-return result.
- **Completion:** verify the exact opaque durable receipt and freshly check claim/admission epochs/deadline plus
  current credential/destination/authority. Commit completion and retire only the delivery copy; any delivery fact
  follows that commit. Safe outcome/status is neither enrollment activation nor launch/signing permission.

## Acceptance Criteria

- [ ] Document public typed invocation, sanitized outcome, receipt-verification and transactional participation
      contracts. Domain repositories own persistence; unsupported sink/authority capabilities fail closed. No cached
      external allow decision, nested transaction or generic unqualified secret-store put can bypass the protocol.
- [ ] A normal attempt persists claim then admission, invokes outside all transactions, and completes only on an exact
      verified receipt. No raw material is accessed after claim alone. Integrity-bound ciphertext must match delivery,
      Agent/credential and destination tuple; never decrypt the authentication envelope as a delivery fallback.
- [ ] Sink idempotency uses delivery ID alone across retries/takeover, bound to original bytes, Agent/credential
      ID/revision and destination identity/binding/write version. Changed bytes/tuple or equal order with another
      binding rejects without writing. Missing/swapped/unverifiable receipts cannot report delivered. Public receipt
      contains no secret digest or read capability. Behavioral sink fixtures prove these obligations, not production adapters.
- [ ] Require immutable versioned staging, nondecreasing per-slot high-water marks and retained deduplication evidence.
      Identical retry returns its receipt without changing selection. Delayed lower-order writes cannot overwrite,
      select or reactivate newer material. Before the sink learns newer package authority, late bytes remain inert:
      consumer selection requires the exact current package/destination tuple, never latest arrival or a sink pointer.
- [ ] Interleave caller revocation, Permission removal, delegation expiry, destination reassignment and credential
      retirement around claim/admission, before materialization, during invocation and before acknowledgement. Denial
      before admission never materializes; after admission an already admitted call may only stage fixed-sink inert
      bytes. Expiry during a call cannot recall bytes. Revoke/regrant ABA and expired/replaced claims reject old completion.
- [ ] Inject committed and rolled-back uncertain admission commits: neither permits decrypt/invoke while unconfirmed.
      Late-returning commits past the recorded deadline cannot start either. Persistence faults and uncertain outcome
      commits produce honest safe states, never guessed delivery success or automatic reissue; TASK-00052 adds restart
      reconciliation, not deferred basic fail-closed behavior.
- [ ] Define/test finite claim/admission/retry/retention defaults, optional valid overrides and invalid combinations,
      including trusted-time/authorization deadlines and TASK-00046 capacity relationships. Preserve existing recovery
      at new-work capacity. Temporary sink/key failure retains bounded original material/version and sanitized retry
      state; permanent/corrupt/expired material fails safely. No routine manual setup or extra human approval is needed.
- [ ] Completion removes delivery ciphertext but not the Agent authentication envelope. Results, status, events,
      audit, serialization, debug and failures expose no raw/ciphertext credential, key path or arbitrary provider error.
      Receipt lookup after completion is not another secret read. Issuance or a receipt does not activate enrollment.
- [ ] Focused path/failure/race tests and consumer-facing contracts cover TICKET-00013 D2/D3/D4 and relevant D5/D6/D7.
      Assert durable state and rejected stale effects, not only calls. Core sink/authority safety cannot be postponed
      to TASK-00054; that later slice integrates all writers and reusable qualification.
