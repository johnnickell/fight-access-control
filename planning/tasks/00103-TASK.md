# Protect Slim and Yii 3 requests through shared PSR-15 admission

## What to Build

Deliver approved slice A of [TICKET-00032](../tickets/00032-TICKET.md): one portable PSR-15 permission middleware and
reusable inward declaration/authority admission, with complete native Slim AND Yii 3 journeys. This is not an
interfaces-only prefactor. Native Symfony/Laravel/CodeIgniter slices consume the inward check/declaration/failure
contract, not Slim/Yii runtime classes or a duplicate implementation of permission policy.

Reuse existing SecurityContext, authenticated User/Agent providers and immutable authority semantics. Consumers
select one trusted authority and supply authentication/context, grants and target scope. Define protected/public/
authenticated-only declarations deliberately; missing/malformed/ambiguous protected declarations are broken
configuration, not implicit public access. Trust matched-target metadata from composition, not caller headers,
route arguments, copied Permission arrays or publicly constructible principals alone.

Implement under the approved capability-first Adapter boundary with Adapter → Application → Domain. Shared policy
stays in existing inward ownership; HTTP classification/presentation belongs at the adapter boundary. Include the
initial Composer/autoload, dependency/architecture, mirrored Adapter tests, PHPCS/PHPStan and exact-coverage/default
suite wiring necessary for this first Adapter feature. No blanket outward dependency, gate exemption or mandatory
production dependency on all frameworks. Native dependencies and registration remain explicit/isolated.

### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and effects |
| --- | --- | --- |
| Integrator enables selected middleware and context/target bindings | No business message | Explicit optional composition, no routes, issuer, seed grants or unrelated adapters installed. |
| Matched protected Slim/Yii 3 request arrives | Existing trusted authentication then inward admission | Permit dispatch only after valid requirements and selected User/Agent authority; deny before protected validation/work. |
| Same process serves another request or nested native path | New/explicitly scoped trusted context | No cached identity or stale matched-route declaration crosses request boundaries. |
| Known refusal or operational fault reaches selected HTTP boundary | Common safe categories/policy/PSR-15 presentation | Deliberate safe classification, validated metadata, one redacted reporting owner and qualified fallback. |

Checking adds no business Command/Query/domain event. Existing authentication retains its actual session/nonce effects;
no per-middleware nonce replay. Consumer use cases protect alternate entry points and target scope independently.
