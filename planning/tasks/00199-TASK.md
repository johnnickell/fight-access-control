# Resolve Python planning and archive tooling

## What to Build

Port `planning_portfolio.py`, `archive_planning.py` and `qualify_planning_portfolio.py` together to PHP and remove the Python implementations and callers. Keep the existing `bin/` commands and use Docker for host invocation. The PHP scripts run directly in a prepared environment without invoking Docker and may use Composer. Update callers, guidance and inventory. Use Fight Agent OS’s `bin/planning-check` and `scripts/planning_portfolio.php` as implementation references for the Docker wrapper and PHP split; preserve AccessControl’s own schema and behavior.

## Acceptance Criteria

- [ ] With the Docker tooling prepared, planning validation stays offline and read-only, rejects stale or invalid records, and reports useful failures. Explicit regeneration preserves generated views and completion rules.
- [ ] Archive dry run and explicit apply retain parity for terminal eligibility, link repair, exits and write boundaries. Qualify in a disposable checkout only; do not archive live work.
- [ ] The production renderer and its qualification run in PHP without Python, host PHP for the wrappers or nested Docker. No product or release policy changes.

## Verification

Select the worktree before implementation. Run direct offline planning/archive qualification and compare outputs, exits and generated views for changed commands. Run `./bin/build` for executable gate-input changes, plus planning, documentation-link and diff checks.
