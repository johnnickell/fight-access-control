## Contracts and Boundaries

- Extend existing FeatureFlag to classes and methods, repeatable in both locations, preserving canonical FeatureName
  construction and declaration-only meaning. Instantiate every relevant native Attribute to validate actual placement,
  multiplicity and arguments; getArguments() alone is insufficient. Update formerly invalid class/repetition fixtures
  coherently while property/parameter/other unsupported targets and malformed arguments still reject.
- Resolve requirements for the trusted actually selected action, deliberately walking applicable class/method ancestry,
  including supported inherited, overridden and invokable forms. Preserve route/action association; unresolvable or
  ambiguous protected targets cannot silently yield no gates. Read metadata without constructing a controller merely
  to inspect it. Explicit trusted bindings cover closures and other supported forms; arbitrary direct PHP calls remain
  unintercepted. Native target extraction and lifecycle qualification belong to TICKET-00050/00051.
- Own the small reusable pure selected-action/ancestry output once, so TASK-00171 consumes it rather than copy the walk.
  Keep this mechanism independent of Feature evaluation, discovery providers, repositories and authentication; it
  neither enables a capability nor creates a generic reflection/security registry, scanner or speculative framework.
  Concrete cohesive names/signatures remain implementation design within these accepted responsibilities.
- Accumulate class, method, inherited/overridden-parent and explicit route requirements conjunctively; child declarations
  cannot remove parent gates. Validate each declaration/registration before deduplicating canonical valid names. Reject
  malformed/contradictory/ambiguous protected metadata instead of choosing an override or silently skipping it. No
  effective Feature declaration means no Feature gate, not public Permission access or authorization to act.
- Align the full FeatureReferences/discovery path and current callers/examples with class/repeated/inherited requirements
  and explicit registrations in this same slice. A method-only getMethods()/getAttributes() loop that omits class or
  overridden-parent references is not complete discovery. Package fixtures model an already selected code scope, not
  a production scanner or proof of real consumer code identity/completeness/freshness.
- Preserve CANDIDATE for provisioning/preparation and CURRENT for safe retirement; complete-empty is valid, while
  unavailable/failed/partial/invalid scans cannot become complete-empty or be relabeled under another scope. Check
  actual preparation, provisioning and retirement paths, not only collection accessors. Keep preparation read-only,
  existing lazy default resolution/new-Feature behavior and complete current-reference/revision guards intact; metadata
  inspection itself performs no lookup/provisioning/transaction/mutation/audit/Event or authorization decision.
- Preserve existing Feature evaluator/model, Permission/public rules and business/reference/writer fences. Coordinate
  existing typing, provisioning/audit and metadata owners once without absorbing their unrelated correction or new audit
  behavior. TASK-00149's native metadata qualification is not a blanket prerequisite or a substitute for this new behavior.
  Evidence/metadata/IDs grant no authority and carry no secrets, raw requests/entities or private diagnostics.
