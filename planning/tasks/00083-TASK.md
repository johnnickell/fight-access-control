# Prevent package builds from silently using an unpatched PHP runtime

## What to Build

Refresh and verify the package-owned PHP build runtime, and repair the build wrappers so a cached base image
cannot silently bypass the required security patch. Require actual PHP 8.5.12 or a later supported patched
runtime before running Composer or requested package commands. This is a build-tooling repair, not an
AccessControl authentication-code change or a claim that this CLI-only environment is remotely exploitable.

John approved this standalone scope on 2026-10-22, then explicitly invoked Build in the main checkout.
Implementation is on `feature/task-00083-php-runtime` from `develop` `d955d2f88cf58a5696814adeebb609a64fff8ee9`.
Priority is prompt security maintenance, ahead of future feature work. There are no TASK dependencies.
Independent acceptance and behavioral QA remain pending; implementation is not consumer remediation or deployment.

## Diagnosis and Reproduction

Inspected clean `develop` at `d955d2f88cf58a5696814adeebb609a64fff8ee9` on 2026-10-22.
The official [PHP advisory](https://www.php.net/archive/2026.php) and
[PHP Foundation explanation](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security)
confirm CVE-2026-109618 and CVE-2026-109619 and the PHP 8.5.12 fix. PHP identifies web-serving installations
as at risk; consumer PHP-FPM, Apache and other request-serving runtimes require their own urgent assessment.

Safe local observation, without network access or repository mounts:

```sh
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --entrypoint php fight-access-control:latest \
  -r 'echo PHP_VERSION, " ", PHP_SAPI, PHP_EOL;'
```

Observed: `8.5.7 cli`. Required post-repair result: an actual supported patched runtime, at least PHP 8.5.12
on the current 8.5 line, verified before package work executes.

`etc/docker/Dockerfile` uses floating `php:8.5-cli`; both `bin/build` and `bin/.container-run` call
`docker build` without `--pull` and without a security-version preflight. A normal cached build therefore
need not retrieve the patched base. `composer.json`'s `config.platform.php: 8.5.4` is resolver simulation,
not evidence of the executing PHP version or an update mechanism.

Confidence is high in the observed old runtime and missing refresh/preflight. No exploit was executed,
no controlled stale-build regression was run during diagnosis, and no compromise was demonstrated. The
implementation must establish its own failing tooling regression before repair. Live/archive TASK search
found no matching repair; GitHub open issue and PR lists were empty immediately before record creation.

## Scope

- In scope: `etc/docker/Dockerfile`, `bin/build`, `bin/.container-run`, a narrowly shared runtime preflight
  if useful, explicit tooling qualification, and affected contributor/runtime documentation.
- Preserve existing command forwarding, image selection overrides, noninteractive build behavior, worktree
  support and the canonical quality gate. Apply the same security admission to both wrapper entry points.
- Out of scope: Domain/Application behavior, consumer Composer minimum changes, dependency-policy redesign,
  production adapters, global developer-tool upgrades, consumer image/deployment changes, incident response,
  credential rotation, release/tag changes and unrelated vulnerabilities from the source article.

## Validation and Permissions

Validate the executing runtime, not only the Docker tag or Composer's simulated platform. Reject obsolete,
unreadable or failed runtime checks. A pull/build failure must not fall back to a cached image and continue.
No silent offline bypass is part of this scope. Preserve ordinary Docker/registry permissions and report
unavailable patched images or network access as prerequisites, not passing evidence. Use isolated test doubles
for failure paths; do not run exploit payloads or mount credentials into diagnostic containers. No authority
is granted to mutate consumer services, rotate secrets, publish, merge or release.
