# Replace timing-sensitive test setup where proof is equivalent

## What to Build

Assess the native Task disconnect, native Subscription early-delivery and Subscription lease-expiry tests identified in the [WF-037 baseline](../wayfinder/research/WF-037-quality-gate-baseline.md). Replace fixed waits with bounded synchronization or control of the actual lease clock only when that preserves what the tests prove. Retain existing waits and document why when an equivalent alternative is not available.

## Acceptance Criteria

- [ ] The disconnect test still exercises a real HTTP disconnect after durable commit, independent completion and a fresh guarded read. The early-delivery test still verifies delivery before the stream ends. The expiry test still proves that an expired lease cannot complete as healthy, using the real lease clock or an equivalent controllable seam, not an unrelated authentication clock.
- [ ] For each changed case, record the original and retained behavior, focused run results and any bounded wait or cleanup behavior. Report timing-sensitive setup separately from a reproduced flake. Reproduce before fixing a confirmed defect, or document why reproduction is unavailable.
- [ ] Keep exact statement and Unit-only line coverage, shipped OpenAPI coverage and unique behavior checks. No production contract changes, test deletions without equivalent proof, new skips or automatic retries. Keep this work distinguishable from the benchmark in [TASK-00193](00193-TASK.md).

## Verification

Select the worktree before implementation. Repeat the affected focused tests under controlled conditions, retaining individual exits, then run the canonical `./bin/build` and save its receipt for any executable changes. Run planning, documentation-link and diff checks.

## Implementation evidence

- Native Task disconnect: the post-commit fixture used a marker and a 300 ms delay. It now signals on a separate loopback connection and waits for release. The test closes the real HTTP socket before releasing the fixture, then still runs an independent producer and verifies the result through a fresh guarded HTTP read.
- Native Subscription delivery: the test used elapsed-time margins to distinguish delivery from completion. The recovery fixture now holds the next read after publishing the notices. The HTTP client must receive the acknowledgment and all expected notifications before releasing that read. The real finite stream must still emit completion and close; the rejection check stays in place. The gate is enabled only for these native delivery tests.
- Subscription lease expiry: retained the six-second wait. Common's execution and DBAL store read the real wall clock directly. Advancing the authentication clock, expiring only the persisted row, or throwing from a stub would not exercise the same elapsed execution lease and would not preserve this proof.
- Both native handshakes use bounded socket waits and close control sockets and the test process on failure. These are fixture changes, not production or coverage-policy changes. The completed baseline run passed; timing sensitivity was observed in setup, not reproduced as a test flake. These runs are not the TASK-00193 benchmark.

The fresh canonical build exited 0 (10,273 tests, no skips), including shipped OpenAPI tests, 11,959/11,959 exact statements and 11,959/11,959 Unit-only executable lines. Planning, documentation links and diff checks passed. Individual exits and the original build receipt are linked in the Work handoff.
