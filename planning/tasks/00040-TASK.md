# Remove deprecated Fight Common contract dependencies

## What to Build

Migrate the maintained AccessControl package surface from Fight Common's deprecated `UnitOfWork` interface to
`TransactionalUnitOfWork`. Update production constructor dependencies, test doubles and fixtures, repository and
consumer guidance, and compatibility notes without changing established transactional callbacks or observable
business behavior. Compare the final maintained surface once against Fight Common 1.2's authoritative deprecated
API declarations and retain the audit evidence in the TASK's ignored run space.

This TASK is the priority implementation prerequisite for TASK-00038 so subsequent credential-delivery orchestration
is built directly on the supported transaction contract rather than introducing more deprecated dependencies.

## Acceptance Criteria

- [ ] Every maintained production constructor and internal collaborator that requires transaction coordination types
      against `TransactionalUnitOfWork`; no production code requires Common `UnitOfWork` or its standalone `commit()`
      method, and no deprecated compatibility bridge is added.
- [ ] Test doubles, anonymous fixtures, type assertions, configuration, repository guidance, and current consumer
      documentation use the supported contract while historical planning evidence remains unchanged.
- [ ] Existing `commitTransactional()` callback boundaries preserve reads, validation, mutation, persistence,
      reference fencing, audit work, callback results, and post-commit success publication.
- [ ] Representative command-handler, authentication-service, Agent-service, and current-Agent-principal tests prove
      successful commit, rollback, callback-result propagation, success-event ordering, existing failure evidence,
      authority fencing, request-local behavior, and unchanged exception identity.
- [ ] A run-local one-time audit compares maintained production code, tests, configuration, and current consumer
      guidance with Fight Common 1.2's deprecated declarations and records that no deprecated Common API dependency
      remains.
- [ ] Consumer migration guidance and `CHANGELOG.md` classify the constructor dependency change as breaking pre-1.0
      compatibility and identify `TransactionalUnitOfWork` as the replacement without claiming certification, tag,
      publication, consumer upgrade, or deployment.
- [ ] Planning records and generated views reflect that TASK-00038 follows this migration and TASK-00039 remains the
      later release-qualification owner.
