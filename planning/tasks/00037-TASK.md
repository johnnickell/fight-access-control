# Model recoverable credential-delivery state and repository contracts

## What to Build

Revise grant-owned activation, password-reset, and email-change delivery entities and repository contracts so the
package can discover due work and safely persist claims, leases, retries, permanent outcomes, expiry, and stale
expected-state rejection without duplicate delivery state. Replace public ciphertext exposure with the narrow
encrypted-material boundary needed by later package orchestration.

## Acceptance Criteria

- [x] Each delivery generation retains its stable ID and gains package-owned retry due time, claim token/lease, attempt
      metadata, typed safe status, and outcome transitions consistent with its owning grant/revision.
- [x] Repository contracts provide deterministic secret-free due-work discovery and enforce complete predecessor/next
      state comparisons for claim, lease recovery, and expected outcome updates through the caller's Unit of Work.
- [x] Grant replacement, consumption, revocation, cancellation, and expiry invalidate stale delivery work and destroy
      ciphertext where required.
- [x] Domain/repository tests prove rollback, claim races, stale revisions, lease expiry, retry-until-expiry, permanent
      terminalization, and no secret-bearing safe view or serialized message.
