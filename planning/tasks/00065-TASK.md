# Protect Permissions referenced by Features

## What to Build

Extend the existing Permission-removal path and atomic reference contract so any referencing Feature blocks removal,
including OFF and ON Features. Cover managed-policy planning/reconciliation and the supported repository removal
boundary, coordinated with TASK-00062's provisioning writes. This delivers a complete integrity outcome, not merely
a reference-count helper or a preflight check that can be bypassed at the write.

John approved this first slice of [TICKET-00017](../tickets/00017-TICKET.md). Existing Role/Agent protections,
Permission assignment tiers, and consumer-owned caller authorization remain unchanged.

## Use Case and Contract

- **Actor/trigger:** an authorized consumer removes a Permission through a supported path, including a managed-policy
  reconciliation that omits the definition. Consumers protect their entry points; no new deletion CLI/API is added.
- **Input/reads:** the expected Permission identity/definition plus authoritative reference state. Inspect references
  by Permission ID across every Feature status, not by Permission name, preview membership, or a paginated subset.
- **Rejection:** a referencing Feature rejects removal. Preserve the Permission and referencing Features, publish no
  removal success, and roll back the enclosing failed reconciliation's other changes. Existing Role/Agent reference
  rejection and changed-definition checks continue to apply.
- **Atomicity:** extend the existing consumer-owned Permission-reference fence to Feature creation and future
  rebinding. The absence decision and removal must remain protected through the enclosing Unit of Work; a stale
  preflight query is not proof. A conflicting creation/reference write and removal cannot both succeed. If removal
  wins, subsequent reference creation must reject the now-missing ID, not choose a replacement Permission by name.
- **Supported paths:** inspect the implementation baseline for all removal paths. The current baseline exposes
  PermissionRepository::remove and managed-policy reconciliation; make preview/planning diagnostics and actual
  reconciliation consistent without relying on preview as the final guard. Do not invent a new Permission-management
  surface just to exercise the invariant.
- **Events/effects:** preserve existing Permission/managed-policy command transaction and post-commit publication
  conventions. The new reference check is read-only; no Feature mutation, principal grant, or new audit subsystem.
  Pre-commit rejection emits no success; publication failure after commit does not undo a successful removal.
- **Tier boundary:** a Feature reference blocks deletion but is not membership and must not introduce a new
  tier-promotion blocker. Reclassification and protected Role/Agent membership continue under existing rules.
- **Consumer contract:** production persistence adapters implement the common fence/constraints; package-owned
  orchestration, interfaces, controlled repositories, and reusable scenarios establish the required behavior.
  Do not ship a production database adapter or claim that an in-memory interleaving qualifies a real database.

## Acceptance Criteria

- [ ] OFF, PREVIEW, and ON Feature references each block Permission removal; multiple Features and references beyond
      a list page cannot be missed. An unreferenced Permission remains removable under existing guards.
- [ ] Managed-policy planning reports a referenced removal as invalid, and the final removal boundary still rejects
      a reference introduced after preflight. A rejected reconciliation rolls back its other mutations and emits no
      managed-policy success fact. Test the real planner/handler path, not just a mocked boolean guard.
- [ ] Existing Role/Agent reference protections and stale-definition rejection remain intact. Feature references add
      neither grants nor tier-promotion restrictions and do not make protected Permissions assignable to Agents.
- [ ] Composed provisioning/removal tests exercise both competing write orders: a committed Feature reference prevents
      removal; committed removal prevents creation using that ID. Losing atomic provisioning rolls back the pass's
      other inserts. Assert persisted outcomes through shared reference-state fixtures, not only method calls.
- [ ] Inventory all supported removal entry points at the implementation baseline, document the common final guard,
      and exercise repository-level and managed-policy paths without a bypass. Preserve safe failure/event ordering.
- [ ] Specify the reference-changing repository obligation used by later rebinding, including no-op validation where
      applicable. TASK-00066 will prove the real rebinding operation against this same fence; do not claim that proof
      from a not-yet-implemented operation or introduce a reverse blocker on it.
- [ ] Publish consumer-bindable removal/creation conflict scenarios and integration guidance covering shared transaction
      participation, schema/adapter compatibility, and consumer authorization. Package conformance and real database
      qualification remain distinct. No adapter migration or release is performed here.
- [ ] Focused reference/removal/reconciliation/provisioning tests and the complete package gate pass with exact
      production statement coverage; actual local evidence and independent review precede completion.
