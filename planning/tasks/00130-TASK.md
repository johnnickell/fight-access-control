rotation conversion coordinated by [TICKET-00038](../tickets/00038-TICKET.md) and
[EPIC-00016](../epics/00016-EPIC.md#agent-command-result-coordination-follow-up). This task owns the dispatch-specific
type relationship and qualification evidence, not the conversion, existing issuance workflow or a new bus.

### Actors, Messages and Results

- Authorized provisioning/rotation callers supply existing secret-free retained operation/Agent/predecessor/name/
  destination intent through the production Commands/handlers delivered by EPIC-00015's separately planned
  [conversion follow-up](../epics/00015-EPIC.md#approved-follow-up--result-preserving-agent-commands).
- Current AgentProvisioningService::provision() and AgentCredentialRotationService::rotate() identify the use cases;
  AgentProvisioningResult and AgentCredentialRotationResult identify today's meaningful safe result contracts.
  Consume the actual accepted replacement names/placement and qualified supplier APIs rather than freeze provisional

  results. A later status Query cannot reproduce an invocation-specific warning automatically. Result propagation
  neither confirms credential delivery/activation/launch authority nor introduces a business Event or permission.

### Behavior and Qualification

- Trace each converted production payload, registration, handler input/result, message creation/metadata operation,
  actual result-capable synchronous bus and owned caller. Prove exact static inference through supported direct
  command invocation and message dispatch; do not silently discard results to fit the installed void CommandBus.
- Use actual independently accepted/qualified tagged Common result-capable contracts with real sufficient-minimum
  and ordinary AccessControl composition. Establish exact supported API names and constraints from evidence, not an
  assumed next release or a local generic interface designed around today's declarations.
- Preserve inward dependencies in native AND static declarations. A Domain Command's annotations must not import
  an Application result DTO. Consume a supported layer-safe association; do not relax architecture checks, copy an
  upstream hierarchy or fabricate a Domain value solely to conceal an outward dependency.
- Positive executable static fixtures prove exact result/warning/optional issuance access and preservation through
  message metadata transformations. Negative fixtures reject mismatched result/handler/payload use, unrelated
  result expectations and claims that actual void dispatch supplies these values; do not invent a ban on ignoring a result.
  Expected negative diagnostics are checked, not suppressed; no unchecked caller casts/assertions substitute for inference.
- Runtime tests invoke the actual converted handlers through configured Common buses and separately prove result/
  failure propagation: confirmed issuance without a warning, confirmed issuance with admitted publication warning,
  indeterminate commit, primary pre-commit failure and authoritative same-key result resolution. Do not use dummy
  forwarding handlers or mocks of the result bus as proof that production dispatch works.
- Use the conversion owner's existing business scenarios/fixtures and authoritative outcome oracle. EPIC-00015's
  conversion retains its own complete behavior tests/gate/independent acceptance; it cannot defer basic dispatch or
  safety to this task. Here qualify that those real outcomes retain exact caller-visible types through dispatch,
  without implementing issuance, changing uncertainty or re-owning authority/recovery acceptance.
- Preserve actual message identity, canonical secret-free intent/round trips and metadata. Invocation results are
  not automatically serializable/public data. Raw generated credentials, authentication/password inputs, ciphertext,
  hashes, provider payloads, diagnostics/causes and unnecessary personal data do not enter messages or warning proof.
- No captured event result, mutable metadata/holder, global result side channel, status-query substitute,
  direct-handler bypass, local bus shim or forwarding facade is allowed. Existing 37 success-only CommandHandlers stay void;
  TASK-00129's adoption is independent of this future result-bearing qualification.
