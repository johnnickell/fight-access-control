# Build the branded consumer docs site and shorten the README

## What to Build

Give a new AccessControl consumer a clear path from the README to installation, first use, capability guides and framework setup. Build one consumer-first MkDocs site from `docs/` with the [official Fight logo](../../docs/assets/README.md). Use [Fight Common](https://johnnickell.github.io/fight-common/) as the benchmark for typography, navigation and visual clarity. Provide a reproducible docs build and validation command that the publication TASK can reuse.

## Acceptance Criteria

- [ ] The shorter README preserves the managed release panel, install constraint, release overview and tagged-doc links. Link to a working repository entry point until Pages is live.
- [ ] The rendered site gives consumers a clear install-to-integration path. Keep contributor standards, release procedures, planning and detailed evidence out of the generated site, not merely out of site navigation.
- [ ] Verify accessible logo legibility, contrast, readable code examples and navigation on the home page and representative guides on desktop and mobile. Compare with Fight Common and retain before/after evidence per the Testing standard.
- [ ] Preserve existing links and anchors needed by readers and release tooling. Do not enable live deployment or perform the bulk retirement of notes in this TASK.

No application Commands, Queries, Events, permissions or persistence change. Invalid site inputs must fail validation without claiming a usable build.
