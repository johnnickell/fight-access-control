- Check returned User/Role/grant identity and applicable authoritative correlation where promised. Distinguish genuine

  configured registration Role is not automatically a caller's 404 or business refusal; validate actual configuration
  versus concurrency intent rather than classify by message text, integer code or generic exception class alone.
- Preserve registration defaults, reserved Super Admin rules, canonical-email uniqueness, invitation versus
  registration origin, complete expected-state comparisons and validated no-ops. Domain owns state transitions.
- Keep User/grant/session effects and adopted audit atomic on the actual connection/fences. Disable/delete recovery
  cancellation, restoration semantics, monotonic authority and competing writers must not weaken for type uniformity.
- Publish existing success facts only after confirmed commit. Notification failure cannot replace the primary fault;
  unknown commit is not rollback and publication failure cannot be labeled pre-commit rejection.
- Refine real arrays/collections/ports and callback result shapes. Native UoW mixed with a local @var describing
  the known owned callback return is sufficient under John's decision; no generic UoW API or redundant check is needed.
- Keep Domain exceptions independent of Application. Translate known outcomes using actual qualified Common intent;
  internal/unknown faults remain safe server failures, not blanket-wrapped business categories. Preserve structured
  validation, secret safety and success-only void results without adding uniform result DTOs.
