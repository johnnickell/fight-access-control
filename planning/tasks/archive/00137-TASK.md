### Outcome and scope

Check permission at the entry point, not again inside invitation correction or registration recovery. Once an
ordinary request has been admitted, it may finish even if that permission is removed while it runs. The next
request must check current permission again. Keep the account-change consistency checks and save enabled audit
with the account/grant changes in the same transaction, or save neither.

Remove `InvitationAdministrationAuthorization` and `RegistrationRecoveryAuthorization`, their handler dependencies
and calls, and unused denial exceptions/test doubles. Update supported constructors, package callers, fixtures,
contract inventories and affected current guides. Use GLOSSARY.md and owning guides rather than the historical
CONTEXT as current authority. Do not implement a permissive callback, ambient trust flag or replacement inner gate.

| Actor and trigger | Commands / Queries / Events | Outcome and effects |
| --- | --- | --- |
| Consumer-admitted administrator corrects a pending invitation | `CorrectPendingInvitation`; existing post-commit fact | Existing eligible User/grant change and enabled audit commit together without a second permission check. |
| Consumer-admitted administrator recovers a pending registration | `RecoverPendingRegistration`; existing post-commit fact | Existing origin, expected-delivery and recovery rules remain; enabled state/audit writes remain atomic. |
| Permission is revoked during or before an invocation | Existing entry admission; no new message or Query | Already-admitted ordinary work can finish; a fresh request is denied before protected dispatch. |
| State, persistence, audit or publication fails | Existing intentional failures and failure facts | Preserve rejection, rollback, uncertain commit and confirmed-commit/publication distinctions. |

Consumer entries still authenticate the real caller and check operation permission and exact target scope before
trusted bus dispatch, including worker/non-HTTP entries. Supplied actor IDs never grant authority. This TASK does
not edit Agent OS, add a package authentication entry, remove unrelated session/email administration ports, or
implement the separate Agent permission-lifetime amendments. Do not broaden it into the original eight-handler audit.
Preserve existing expected-generation inputs where supplied; adding a new invitation intent contract is not implied.
