### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and effects |
| --- | --- | --- |
| Trusted producer issues supported requests; caller reads them | Owning Common issuance/state operations | Independently admit issuer and complete protected request disclosure; retain server-authored validation privately. |
| Agent submits partial/full input or confirmation | Owning Common input Command/method handling | Current caller/Task/operation/request/group/expiry binding and scope before protected validation and atomic admission. |
| Consumer observes accepted answers and reaches protected continuation | Owning Common observation/consumption contract; consumer work remains separate | Recheck current original authority/scope and single-use admission; acceptance is not execution approval or receipt. |

Common owns mutation/consumption/state/event/commit effects. Ordinary envelope validation remains Common-owned and
may precede protected validation; do not promise authorization before all request-shape parsing. Checks introduce
no business event/grant and replay no authentication nonce. Consumer decides destructiveness and actual effects.

## Acceptance Criteria

- [ ] Real AccessControl authority and consumer scope compose with actual Common issuance/read/input/continuation handlers
  and retained state. Independent operation Permissions apply on direct bus/worker and actual method paths; a prior
  read/answer/create, handle, capability declaration or human role grants no mutation or continuation authority.
- [ ] Denial precedes protected retained-request validation, answer/confirmation admission and disclosure. Cross-caller/
  Task/operation/original-arguments/request-contract/group/expiry substitutions cannot expose or consume another
  caller's input. Use verified retained server-authored contracts, not client-defined runtime validation or mutable
  replacement operation definitions. Preserve normal Common outer validation and finite envelope checks.
- [ ] Actual partial/empty/all-ignored/mixed/invalid submissions retain Common's semantics: all active entries validated
  before atomic batch admission, remaining requests stay outstanding, inactive keys grant nothing and execute no
  protected validator. Preserve lifetime immutable request identities, accepted answers and bounded bookkeeping; no
  truncation/reuse or hidden payload archive to invent indefinite guarantees.
- [ ] Partial affirmative responses never admit destructive continuation. Every required confirmation must accept;
  decline/cancel retires the relevant group without implying whole-Task cancellation. Bound caller/Task/operation/
  request/group/expiry and durable single use prevent transplant/replay. Actual Common consumption, failure and
  uncertainty behavior never restores consumed admission or authorizes blind redispatch/exactly-once external effects.
- [ ] Input admission is independent of continuation. TASK-00088 rechecks verified original Agent/credential/direct
  Permissions and consumer scope under synchronized admission before each new protected continuation; revocation,
  rotation/scope/Permission change or resolver fault denies the next step without nonce replay or credential switching.
  Producer/worker authority does not replace original caller authority. Reuse the existing continuation guard;
  production authority-writer synchronization is not newly implemented or qualified by this package integration.
- [ ] Real duplicate/conflicting-answer and producer-terminal races retain accepted evidence/outstanding state and
  terminal winners. Precommit/commit/response/post-commit/consumer faults preserve truthful outcomes without unrelated
  transaction effects. Actual cancellation-intent races belong to TASK-00100, not a reverse blocker here.
- [ ] Preserve independently authorized complete state/input reads and safe protocol acknowledgments/errors. No public
  status setter, partial extension advertisement, private validator/answer/binding diagnostics or full-state generic
  feed. Ordinary stateless interaction/exact-key/replay/confirmation contracts are not relaxed by Task-specific input.
- [ ] Verify implemented/independently accepted/qualified tagged input/confirmation/continuation APIs and sufficient Common
  minimum with exact source/version/lock/minimum-runtime evidence. Document separate grants/bindings/consumption/current
  checks/bounds/failure/race/consumer limits; update CONTEXT.md. No guessed PHP API/version or legacy fallback.
- [ ] Focused real authority/handler/retained-input/provider-count/confirmation/effect/race/fault tests cover owned
  statements exactly. Full package gate and independent Review/behavioral QA accept; fixtures prove package admission,
  not actual consumer external effects, DB/authority fencing, trusted handoff, cryptography or worker execution.
