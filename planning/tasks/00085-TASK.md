# Authorize exact Resource discovery and reads

## What to Build

Deliver the Resource journey in [TICKET-00026](../tickets/00026-TICKET.md): reusable conjunctive direct Agent
Permission requirements composed with Common's real Resource discovery and exact-read hooks. Consumers can expose
permitted metadata and bytes without treating prior discovery, a saved URI or another capability's link as authority.

Use the existing trusted ordinary-request principal provider and Common's neutral `McpResourceAvailability` contract.
Define validated stable requirement association with the actual configured Resource/provider contract; providers
may emit equivalent fresh metadata objects. Do not copy Tool-definition object-identity rules, freeze dynamic
providers into a speculative Tool-style registry or introduce a second URI resolution/normalization algorithm.
Reject invalid static composition where observable and deny unknown/unmapped runtime identities; no implicit
public fallback, prefix grant, caller-supplied authority or automatic Permission provisioning.

Keep production behavior within existing Application/Domain ownership and use public Common contracts. This
feature needs no storage adapter, new endpoint, content provider implementation or independent prefactor TASK.
Consumers retain content ownership, relationship/scope policy and any provider-backed business Query admission.

### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and side effects |
| --- | --- | --- |
| Integrator associates Resource requirements | N/A; static composition | Validate nonempty canonical Permission requirements and configured identity association without opening content or creating grants. |
| Agent requests Resource discovery | No new business message | Evaluate current Permission admission before disclosure/pagination; hidden metadata/counts stay concealed. |
| Agent reads an exact Resource, including an owned unlisted URI | Common owns provider lookup/open; no new AccessControl Query | Admit independently of listing before content opening; owning providers retain existing use-case checks. |
| Agent follows a saved URI, Tool/Prompt link or later page | N/A until admitted provider work | Fresh request authority applies; cursor/link/cache possession grants nothing. |

Permission evaluation mutates no business state and emits no new Domain event. Existing authentication nonce
consumption and authority fences remain request-scoped; all descriptors reuse that request's provider. Selected
providers alone own admitted reading, streaming cleanup and any independent business use case.

## Acceptance Criteria

- [ ] **Validated requirements and identity:** Every protected association has nonempty valid canonical
  `PermissionName` requirements, all checked conjunctively against direct Agent authority. Missing, malformed,
  conflicting or observable invalid associations reject composition; unknown/unmapped runtime identities deny.
  Legitimate fresh metadata objects for the configured exact identity work without weakening ownership checks.
- [ ] **Real list and direct-read paths:** Actual AccessControl authority resolution composes with real Common
  Resource discovery/read behavior, not only a Boolean stub. Permitted metadata filters before Common ordering/
  pagination. An independently admitted owned URI can be read directly without prior listing, including a provider's
  intentionally unlisted identity. Denial is tested for every missing requirement and unresolved authority.
- [ ] **No denied content opening or lookup escape:** Denied/unknown reads never open content streams. Common's
  duplicate ownership and descriptor consistency checks remain intact, including concealed collisions. Encoded
  aliases, traversal, normalized/fallback lookup, stale links and forged identities cannot select another target.
  Permission evaluation neither prefetches content nor turns a URI into a filesystem/network instruction.
- [ ] **Fresh request authority:** Reuse one trusted provider/principal across decisions within the request rather
  than replaying its nonce per descriptor. Fresh later requests/pages/reads observe revocation, credential rotation,
  Permission removal and regrant; already resolved short requests retain their documented snapshot semantics.
  Caller contexts are isolated, discovery/read caching stays private with zero TTL, and no filtered catalog or
  authorization decision is cached across requests.
- [ ] **Truthful safe failures and output:** Protect metadata, names, links, counts, cursors and bodies. Policy/
  provider/operational faults follow Common's actual safe boundary, not raw exception messages, permissive admission
  or fabricated empty/partial success. Distinguish deliberate authority denial from operational failure; do not
  blindly copy a Tool-only neutral-failure policy into Resource listing. Permitted results preserve exact bytes,
  metadata, stream cleanup and finite encoded bounds without executing instructions or scripts.
- [ ] **Supported dependency and documentation:** Verify actual accepted/tagged Common composition and the supported
  minimum, recording exact version/source/lock evidence; make only necessary dependency changes during authorized
  implementation. Update Resource Permission composition guidance and `CONTEXT.md`, including exact identities,
  dynamic metadata, request lifetimes, failure behavior and separate consumer scope/containment obligations.
- [ ] **Complete verification and acceptance:** Focused allow/deny/fault, provider-open counts, freshness and
  minimum-version tests cover owned statements exactly; the full canonical package gate passes with complete
  log/exit/receipt. Independent technical Review and behavioral QA accept the implemented subject. Controlled
  repositories/providers/streams qualify package composition, not deployed storage, cryptography or client runtime.
