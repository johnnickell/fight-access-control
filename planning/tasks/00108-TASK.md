# Move Agent MCP presentation and family bindings into adapters

## What to Build

Deliver the complete MCP-ownership slice of [TICKET-00033](../tickets/00033-TICKET.md): move existing protocol-facing
Agent integration outward while preserving genuine inward policy and the actual Common invocation/bus paths.
Normally one behavior-preserving PR across source, mirrored tests and current composition documentation.

### Actors, Messages and Effects

Integrators compose Tools/Resource/Skill availability through canonical Adapter classes. Admitted Agent profile
reads still dispatch GetAgentProfile; updates still synchronously dispatch UpdateAgent and retain AgentNameChanged
publication only for committed changes. Discovery/availability add no business message, grant or commit. Existing
request authentication retains nonce consumption; rejected capability admission performs no protected work.

### Scope and Caller Boundary

- Move GetAgentProfileTool, UpdateAgentProfileTool, AgentProfileToolFailures, Tool catalog/permission attribute,
  Resource/Skill permission bindings/catalogs and their Common availability implementations from Application into
  Adapter/Mcp/{Tool,Resource,Skill}/Agent. Keep short names where they still describe the responsibility.
- Keep CurrentAgentPrincipalProvider, authenticated authority, Permission policy, transport-neutral signed-request
  contracts and synchronized continuation in Application/Domain. Any genuinely reusable decision shared with
  adapters stays inward without importing Common MCP descriptor/registry/presentation types into that decision.
- Preserve the chain Common invocation → availability → profile Tool → configured Command/Query bus → handler →
  Domain repository. Do not add a profile Application facade, duplicate schemas, subclass Common final Tools or
  move business/transaction orchestration into an adapter. Direct handle/bus paths retain consumer authorization.
- Use transport-neutral Adapter/Mcp, not speculative Http/V1 folders. Optional HTTP/native middleware remain
  separate. Reconcile architecture/autoload/test coverage wiring for moved types without exclusions or gate weakening.
- Update constructor/named-argument callers, actual registrations/attributes/reflection, tests, public composition
  examples, current CONTEXT/README/Unreleased breakage notes. Remove retired AccessControl names directly under ADR 0011.
- Use currently qualified Common contracts for this local relocation. TASK-00110 separately adopts newly released
  canonical upstream names; neither clone future signatures nor add compatibility aliases to avoid that later change.
