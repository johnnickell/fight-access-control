# Revalidate bound Agent authority before protected continuation

## What to Build

Deliver the complete [TICKET-00028](../tickets/00028-TICKET.md) outcome in one independently reviewable feature
TASK: establish trusted original context from admitted Agent authentication, then revalidate current authority at
each new protected disclosure/background-continuation boundary without replaying authentication. Binding creation
and current checks stay together because neither alone delivers safe continuation admission.

Reuse existing Agent/principal/Permission contracts and exact current Permission resolution. Preserve
`CurrentAgentPrincipalProvider`'s ordinary immutable request snapshot; do not turn it into a stream/job singleton
or reconstruct it repeatedly over a consumed signed request. Keep reusable behavior in existing Domain/Application
ownership, with runtime/persistence/scope collaborators behind the appropriate inward contracts.

Specify the current public binding/check API, binding provenance and validity/lifetime, supported trusted worker
handoff, safe integration outcomes and check-to-admission synchronization/fence contract during implementation.
Any necessary authority-read/admission repository contracts belong to this TASK, not a separate layer-only
prefactor. Existing `getById()`/`getByIds()` reads are not by themselves proof of atomic protected admission.
Consumers retain authoritative scope and invoke the checks at each applicable runtime boundary; the package
adds no stream manager, executor, relationship model, token issuer or global authority store.

### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and side effects |
| --- | --- | --- |
| Consumer authenticates an ordinary request | Existing provider/nonce transaction; no new business message | Retain signature/replay admission and one request-local principal snapshot. |
| Trusted integration establishes continuation context | N/A; binding rooted in admitted authentication | Bind original Agent and credential identity/revision with defined validity/provenance; no authority from copied principal fields. |
| Runtime is about to emit a queued item or perform a protected continuation step | Authoritative reads/admission through owned contracts; no new business Command/Event merely for checking | Check current Agent, original credentials, all required direct Permissions and current consumer scope before protected admission. |
| Runtime consumes retained accepted input for protected work | Owning runtime retains actual input/effect operations | Current continuation admission remains independent of earlier input acceptance; no stale grant or restored consumed admission. |
| Authority/scope changes, binding verification fails or a resolver faults | N/A | Fail closed with safe integration output; no fallback to an earlier allow, switched credential or unredacted diagnostic. |

Revalidation grants nothing and does not mutate business aggregates, emit a new Domain event or consume a nonce
per frame. Initial authentication retains its existing nonce transaction and fences. Any synchronization/resource
participation must be specified explicitly; acquiring an admission fence is not a business mutation or a guarantee
of future authority. Runtime owners retain all admitted effects and their actual transaction/recovery behavior.

## Acceptance Criteria

- [ ] **Trusted binding:** Context is rooted in successfully admitted authentication. Specify and test issuance/
  provenance, validity/lifetime and supported trusted handoff, including worker boundaries. IDs, serialized/publicly
  constructible principals, copied Permission lists, protocol metadata and heartbeat/handle possession cannot alone
  create an admitted binding. A handoff lacking required verification fails closed; no new bearer credential or
  session issuer is introduced to implement this contract.
- [ ] **Current Agent and original credential:** Each protected boundary authoritatively verifies the Agent remains
  active and matches the original credential identity/revision. Missing/revoked Agent, rotation/replacement or
  mismatched binding denies; never silently adopt the Agent's new credential or replay the original signed request.
  Repeated rechecks perform no additional HMAC authentication or nonce consumption.
- [ ] **Current direct Permissions and scope:** Resolve actual current assignments and exact Permission definitions;
  every required canonical Permission must hold. Grants/removals/regrants and definition changes affect subsequent
  checks; initial Permission snapshots/revisions are not current grants. Missing/mismatched definitions and resolver
  faults fail closed. Trusted consumer scope is re-evaluated independently; a target selector, human Role, OAuth
  scope or operation reference is not a relationship grant.
- [ ] **Precise synchronized admission:** Specify the point at which current Agent/credential/Permission/scope
  checks admit the bounded protected action, any required repository/fence contracts and participation/failure rules.
  Prove changes before admission deny and document behavior of changes after admission. Coordinate with relevant
  authority writers; unsupported or unverifiable synchronization cannot become an allow. Separate reads, a cached
  principal or a detached Boolean are not represented as an atomic disclosure fence. Do not claim retroactive
  revocation, retraction or safety of actual consumer races from sequential fixture checks alone.
- [ ] **Guarded runtime scenarios:** Controlled queued-disclosure, background-step and applicable retained-input-
  consumption fixtures use real package authority/Permission resolution and trusted consumer scope admission.
  Revoke/rotate/remove Permission/change scope or inject verification faults between boundaries: the next protected
  output/effect/consumption does not occur. Prior successful checks/input acceptance do not supply continuation
  authority or restore consumed input admission. Actual Common Subscription/Task runtime integration stays with
  TICKET-00030/00031; invent no future protocol signatures here.
- [ ] **Ordinary request contract retained:** Existing successful and rejected request-scoped admission behavior,
  nonce transaction/replay rules, fresh later requests and short-request snapshots remain intact. New continuation
  checks are explicit and do not retroactively cancel a request already admitted under its documented snapshot.
  No stale-principal singleton, periodic unconditional lease, cross-boundary cached allow or silent identity switch.
- [ ] **Safe outcomes and truthful limits:** Define neutral binding/admission failure behavior suitable for later
  protocol-specific translation. No signed request, nonce, secret/credential material, binding contents, private
  causes or Permission/scope explanations enter public output or unredacted logs. No universal HTTP envelope or
  competing reporting owner. Denial proves no further admission, not forced job cancellation, rollback, compensation,
  exactly-once effects, removal of disclosed bytes or proof that an existing worker stopped.
- [ ] **Guidance and dependencies:** Document chosen binding/check/fence contracts, trusted handoff/lifetimes,
  consumer invocation at every protected boundary, authority-writer participation, failure/race semantics and
  explicit actual-consumer qualification gaps. Update `CONTEXT.md` and affected authority/MCP composition guidance.
  Verify any newly used Common declaration against its supported tagged minimum; do not guess live APIs, adopt
  development snapshots as stable or add legacy readers/aliases/migration machinery contrary to ADR 0011.
- [ ] **Complete verification and acceptance:** Focused allow/deny/fault, forged context, validity/handoff,
  credential/Permission/scope change, synchronization and nonce/effect tests cover owned statements exactly. Full
  canonical package gate passes with complete output, actual exit and local receipt. Required independent Review
  and behavioral QA accept the implementation; package fixtures identify unexecuted real persistence/cryptography/
  scope-authority/container/worker lifetime and concurrency qualification rather than asserting production safety.
