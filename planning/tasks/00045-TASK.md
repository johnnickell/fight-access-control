# Reconcile protected managed policy without forbidden membership

## What to Build

Reject a managed definition that attaches a `SUPER_ADMIN_ONLY` Permission outside authoritative managed
`ROLE_SUPER_ADMIN`. Reject promotion of an existing managed Permission while any custom Role, ordinary managed Role,
or Agent still holds it. Integrate the Role and Agent tier fences from the prerequisite TASKs with reconciliation
so a grant and promotion cannot both succeed under controlled concurrent or stale-state interleavings.

## Use Case and Effects

| Actor and trigger | Commands / queries | Events | Effect and result |
| --- | --- | --- | --- |
| A consumer supplies managed policy | `ReconcileManagedPolicy`; existing `PreviewManagedPolicy` remains read-only | `ManagedPolicyReconciled` after successful commit | A protected Permission may appear only on authoritative managed `ROLE_SUPER_ADMIN`; invalid definitions fail before policy mutation. |
| A consumer promotes an existing managed Permission | `ReconcileManagedPolicy`; authoritative Role/Agent membership reads | Existing failure Event on rejection; no success Event | Forbidden custom-Role, ordinary managed-Role, or Agent membership blocks the entire promotion. No membership is automatically removed. |
| Grant and promotion interleave | Existing custom-Role or Agent grant plus `ReconcileManagedPolicy` | Success Event only for committed operation | Grant-first blocks promotion while membership remains; promotion-first blocks grant. Losing operation has no partial write. |

## Permissions, Validation, and Compatibility

- Consumer-managed policy declares Permission names and tiers. The application builder protects reconciliation and
  grant entry points; this TASK adds no caller authorization, scope check, HTTP response, or protected-name list.
- Validate the managed flag and exact `ROLE_SUPER_ADMIN` name together. Malformed references, duplicate/mismatched
  Role identity, and forbidden protected membership fail closed before reconciliation changes authority.
- Promotion reads authoritative Role and Agent memberships and preserves the checked state through the same Unit of
  Work as tier change. Repository contracts and in-memory implementations must make the grant/promotion conflict
  outcome explicit; the concrete persistence-adapter lock method is consumer-owned.
- Preserve exact managed-policy reconciliation, stable IDs, existing no-op behavior, rollback, safe failure Event,
  and post-commit `ManagedPolicyReconciled` publication. Document pre-1.0 contract implications without claiming a
  tag, Agent OS adoption, or historical data migration.
