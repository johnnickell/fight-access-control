# Make stale planning failures diagnosable

## What to Build

Trace the four sampled failures in the [WF-037 baseline](../wayfinder/research/WF-037-quality-gate-baseline.md) to the exact trees CI tested, including PR merge results where applicable. Identify the authored inputs and generated views that disagreed. Fix a confirmed cause or improve diagnostics so maintainers can see which views are stale, what revision was checked, and how to regenerate the views locally. Keep CI validation read-only and fail-fast under the [single-gate ADR](../adr/0002-single-quality-gate.md).

## Acceptance Criteria

- [x] Record each checked revision, the mismatch and its cause, or the exact missing evidence. Do not infer a generator bug from stale output alone.
- [x] Current views pass. Stale views produce a nonzero exit and an actionable diagnostic without modifying the tested tree. Capture a reproducing check before fixing any confirmed defect; if historical inputs are unavailable, document why and qualify a representative mismatch directly.
- [x] The existing gate still invokes the same authoritative check. No automatic regeneration, retry or skip in CI; no package API, authorization or persistence changes.

## Verification

Select the worktree before implementation. Run `./bin/planning-check` on current and deliberately stale inputs in an isolated checkout, capture exits, and verify no writes. Qualify tooling directly, not via product tests. Run `./bin/build` for executable gate-input changes, plus planning, documentation-link and diff checks. Distinguish historical hosted evidence from fresh local proof.
