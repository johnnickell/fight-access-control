## Contracts and Boundaries

- Add an optional last nullable AuditEvidenceRepository. Omitted/null intentionally disables durable audit; configured
  failure cannot discard evidence or fall back to disabled execution. Add explicit optional typed actorId at the
  Command boundary, not on every discovered Feature. Trusted autonomous callers supply SystemId::fromString(Uuid::NIL)
  once per Command; preserve a real originating User/Agent where applicable rather than overwrite it in a worker.
  No login/system account/additional human approval, ambient resolver, label parsing or missing-data fallback.
- Discover complete CANDIDATE references before the existing single mutation transaction; no attribution check need
  precede discovery. Empty/all-existing passes require no audit-only actor input, even with auditing enabled. If a
  missing Feature requires creation with audit enabled, validate provenance before its first audited mutation.
  Disabled execution gains no new audit-only input; existing business-required validation and authorization remain.
- Explicitly add one record per meaningfully created Feature in that same actual batch transaction/connection before
  commit, with unique evidence ID, typed Feature/Permission relationship, initial revision without predecessor,
  trusted outcome time via the existing Application Clock contract and shared real Command correlation. Do not infer
  evidence from returned Events, invent stored Feature timestamps, or record every lookup/helper/repository step.
- Preserve canonical immutable names, OFF/revision-1 creation, lazy default resolution and all existing choices/
  broken binding identities. No missing names means even invalid unused configuration stays unused. Any existing
  Permission tier is eligible; the reference is not a grant. Do not create Permissions, repair/reset existing rows,
  delete unregistered rows or turn incomplete/wrong-scope discovery into a complete empty inventory.
- All new Features and evidence commit together, using atomic ID/name uniqueness and per-insert Permission-reference
  fences. A late audit-write, insertion, reference or commit failure rolls back the whole staged batch, never a
  concurrent winner. Retain actual primary throwable and both uncertain-commit outcomes. A fresh retry consults
  authoritative storage; committed existing rows create no duplicate evidence, event replay or history backfill.
- After commit, ordinary partial/both-publisher failures leave all created Features/evidence committed and propagate
  the primary failure. Preserve existing fact order and void return; no issuance warning result, outbox or reliable
  publication claim. Completion proves neither preparation, availability, activation nor administrative authority.
- Evidence contains bounded action-specific admitted facts, not raw inventory/configuration/message/plan/entity
  snapshots, credentials/hashes/ciphertext, diagnostics or unnecessary personal data. Free text needs field-specific
  admission; records are not automatically public/log output. No audit-only transaction, UoW/repository interception,
  helper duplicates, durable rejected-attempt store or generic replay/deduplication framework.
