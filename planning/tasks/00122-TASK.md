### Evidence and Attribution Contract

- Reuse AuditEvidence and AuditEvidenceRepository::add(), not a parallel audit service. Evidence has a unique non-nil
  record identity, direct typed actor, typed primary subject, package-defined action and trusted outcome occurrence
  time. Include actual applicable relationships, authoritative before/after revisions and real message/operation
  correlation. Preserve scoped operation identity and complete Role revision/incarnation semantics; never fabricate
  nonexistent predecessor/successor state for creation/removal.
- Support demonstrated User, Agent, Role, Permission and Feature identities, plus session/grant/delivery/operation
  references where their actual outcomes require them. Test shared subject/revision contracts here without adding
  currently unaudited Role/Feature handlers or a generic unrestricted subject type/ID/object bag.
- Use UserId, AgentId and TASK-00121's SystemId/AnonymousId directly. Preserve kind alongside ID in the supported
  evidence construction/hydration/persistence representation; equal UUID text must not collapse actor kinds.
  Concrete cohesive factories/values remain implementation choices within the accepted contract, not permission
  to add an actor wrapper, arbitrary registry, diagnostic payload envelope or generic orchestration framework.
- Replace arbitrary actor labels with explicit trusted typed provenance. Existing string-bearing Commands and
  authorization outputs are not automatically UUIDs: do not parse labels into guessed identities, substitute nil
  actors or infer identity from raw requests. Declared public registration/reset-request semantics may explicitly
  establish AnonymousId; deliberate autonomous work may explicitly establish SystemId, never as missing-data fallback.
- Carry necessary typed attribution through directly affected inputs/ports and current canonical message round
  trips. Preserve sufficient existing actor data, originating User/Agent attribution through workers and existing
  business-required actors. Keep real-invoker/delegation authorization and target/scope/fence checks distinct from
  evidence attribution; do not grant authority merely by supplying an ID or introduce an ambient principal resolver.
- Capture actual outcome time from existing trusted operation clocks/timestamps, not database insertion or message
  creation time. Supply actual incoming message/retained-operation correlation without retaining raw messages.
  Evidence identity/correlation is not universal deduplication or permission to change retained keys.
- Replace unbounded context with bounded action-specific typed/validated facts. Exclude credentials, tokens, hashes,
  ciphertext, raw messages/entities/issuance payloads, diagnostic exceptions and unnecessary personal data. Free-text
  reasons need explicit admission/redaction, not a string/regex claimed to guarantee secret freedom. Evidence is not
  automatically safe for public API/log responses.
