## Implementation

The [migration inventory](../../docs/engineering/python-tooling-inventory.md) records the 24 Python files tracked
at implementation start (23 were noted during planning), their callers, migration owners, and the MkDocs exception. The shared gate now calls
`php scripts/contract_inventory.php` directly. The [inventory procedure](../../docs/engineering/contract-inventory.md)
explains the separate qualification and how earlier reports and candidate-bound judgments are handled.

Work compared both implementations: 566 files and 22,387 boundaries matched, except for the expected tool and
candidate hashes. PHP loaded the Python report with no drift. Paired fixtures matched success, drift, parse-error,
help and invalid-usage exits. The separate PHP qualification passed 36 cases; Composer's `--no-dev` autoloader
excluded the tooling namespace. The canonical Work handoff records the full gate and exact candidate.

The REV-001 repair restored unique long-option abbreviations from the Python CLI. The separate qualification
checks both value forms, abbreviated switches, and usage exits for ambiguous or unknown options.

The REV-002 repair preserves separate path values such as negative integers, negative decimals, and a lone hyphen.
The qualification checks that accepted values reach discovery and replace stale output with an incomplete diagnostic
on failure. Missing values and options in place of values still fail with usage exit 2 and write no report.

The REV-003 repair lets help exit successfully after unrecognized options or stray positionals, unless an
actual parser error occurs first or `--` ends option parsing. The separate qualification also checks short help
clusters and rejected explicit values. A 54-case sweep against the exact Python baseline in the prepared
runtime matched exit codes, help versus usage errors, and diagnostic report behavior in the sampled cases.
