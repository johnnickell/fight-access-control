# Audit User creation, recovery and administration

## What to Build

Deliver optional explicit atomic audit for all eight account lifecycle handlers owned by
[TICKET-00044](../tickets/00044-TICKET.md), using TASK-00122's evolved evidence contract. This owns actual family
wiring/admission and meaningful lifecycle outcomes, not another shared-model replacement or User capability redesign.

### Complete Use Cases

| Commands / corresponding handlers | Actor, trigger and required outcome |
| --- | --- |
| InvitePendingUser, RegisterUser | Trusted invitation initiator or deliberately anonymous public registration; committed pending User and required activation work receive truthful evidence. |
| CorrectPendingInvitation, RecoverPendingRegistration | Authorized administrator changes existing pending authority; preserve target checks, private-invitation/registration origin and replacement delivery correlation. |
| EnableUser, DisableUser, DeleteUser, RestoreUser | Authorized lifecycle administration; evidence reflects authoritative committed state/revisions and relevant coupled effects, not incidental repository writes. |

Own necessary current Commands, actor admission, constructor/named callers, directly affected fixtures/assertions
and current guidance/examples. User Role membership belongs to TICKET-00045. Invitation delivery/resend/retry/expiry
belongs to TASK-00124; synchronous activation/authentication belongs to TASK-00127. Existing Queries remain read-only
and existing success/failure facts retain their publication behavior; no new audit Query, route or permission grant.

### Behavior and Validation

- Give each owned handler an optional last nullable AuditEvidenceRepository argument. Omitted/null intentionally
  disables durable audit; configured evidence failure never enables no-op/fallback execution. Preserve existing
  business-required actors; add optional typed provenance only where absent and necessary under the accepted policy.
- Use direct originating UserId/AgentId or explicitly declared AnonymousId/SystemId semantics. Public registration
  may explicitly establish AnonymousId, not the newly created target User as an authenticated initiator. Workers
  retain original admitted provenance; no label parsing, ambient principal lookup or missing-actor substitution.
- With auditing enabled, validate required attribution before the first mutation requiring evidence. Discovery and
  validated no-change may precede that requirement; disabled/pure no-change execution gains no new audit-only actor
  obligation. Attribution grants no permission and cannot replace retained entry/target authorization.
- Explicitly add typed evidence within the actual handler mutation transaction/connection before commit. Use trusted
  outcome time, authoritative applicable revisions/relationships and actual message/grant/delivery correlation.
  Creation/restoration do not fabricate state or predecessor/successor revisions. Keep invariant decisions Domain-owned.
- Preserve canonical-email uniqueness, registration default Role eligibility/reference fences, pending origin,
  recovery authority, grant replacement/single-use, expected-state/CAS and coupled lifecycle/session/grant/delivery
  persistence. Bulk session/grant cancellation is part of its owning account outcome, not permission for duplicate
  helper-generated records. No new actor class bypasses Domain or target policy.
- Meaningful committed lifecycle changes get enabled evidence; validated no-change/rejected/rolled-back work gets
  no committed-mutation record. Preserve admission on no-change branches rather than skipping authorization/fences.
- Audit failure before commit or concurrent losing mutation rolls back required staged state/evidence. Preserve
  primary faults, uncertain commit and ordinary post-commit publication failure; committed evidence survives later
  publisher/subscriber failure. Do not extend the Agent issuance warning exception to User lifecycle operations.
- Use bounded action-specific safe context; exclude credentials, tokens, hashes, ciphertext, raw messages/entities,
  diagnostic exceptions and unnecessary personal data. Free-text reasons need explicit safety admission. Evidence
  is not automatically authorized public response/log data.
