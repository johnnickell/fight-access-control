# Enforce tier eligibility on custom Role grants

## What to Build

Make the real custom-Role membership commands grant only an authoritative `ADMIN_SAFE` Permission. Validate before
the idempotent no-op path and preserve tier authority through the transaction's Role write. Remove the remaining
actor-only `RoleAdministrationAuthorization` dependency from grant/revoke handlers and retire that port after
[TASK-00042](00042-TASK.md) removes its lifecycle-handler usage.

## Use Case and Effects

| Actor and trigger | Commands / queries | Events | Effect and result |
| --- | --- | --- | --- |
| A consumer grants a Permission to a custom Role | `GrantPermissionToCustomRole`; no new Query | `CustomRolePermissionGranted` only after a real commit | An authoritative `ADMIN_SAFE` grant succeeds; protected, missing, malformed, stale, or managed-Role targets fail without a partial change or success Event. |
| A consumer repeats a grant or revokes membership | `GrantPermissionToCustomRole`, `RevokePermissionFromCustomRole`; no new Query | Existing membership Events on real changes | No-op grant still validates authoritative tier. Eligible no-ops and revocations retain existing desired-state behavior and event ordering. |

## Permissions, Validation, and Compatibility

- The application builder protects API, CLI, worker, and direct command-bus entry points. Package actor IDs remain
  provenance; this TASK adds no caller, target, or scope authorization decision. A Super Admin caller does not
  bypass protected-tier rejection.
- Resolve the target Role and Permission inside the handler Unit of Work. Reject missing/inconsistent authority and
  protected grants before mutation or no-op success. Runtime commands still cannot mutate managed Roles.
- Strengthen the relevant Role repository reference contract and package in-memory seam so an authoritative tier
  change cannot race a grant into forbidden committed membership. [TASK-00045](00045-TASK.md) owns end-to-end
  grant/promotion proof with reconciliation. The adapter chooses its locking method.
- Remove the actor-only Role administration port and now-unused test doubles/exceptions once no handler needs them.
  Preserve serialized Command/Event shapes, transactional rollback, failure Event, and post-commit success order.
  Document the accepted pre-1.0 constructor change for consumers.
