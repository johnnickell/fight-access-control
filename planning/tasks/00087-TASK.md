## What to Build

Deliver the complete [TICKET-00027](../tickets/00027-TICKET.md) outcome in one independently reviewable feature
TASK: validated nonempty conjunctive Agent Permission requirements composed with Common's actual Prompt definition/
availability contracts for `prompts/list` and independent `prompts/get`. Consumers can protect Prompt metadata and
content without treating a name, previous listing/get or linked identity as authority.

Reuse trusted ordinary-request Agent authority and public Common Prompt contracts. Specify the stable validated
association between requirements and actual registered definitions during implementation; missing, malformed,
conflicting and unknown associations cannot silently become public. Common snapshots immutable registration
metadata and owns naming/duplicate rejection; do not create a competing Prompt registry or naming algorithm.
All canonical `PermissionName` requirements are direct Agent checks, not OAuth scopes, human Roles or Prompt arguments.

Common owns lazy selected-provider processing, outer request and declared string-argument validation, complete
message/link output, finite definition/input/result/envelope bounds and safe unknown/denied/internal errors.
Admission precedes declared-argument validation and selected-provider processing; Common's outer request-shape
validation still occurs earlier. Listing and permission evaluation must not construct Prompt bodies or prefetch
linked content. Preserve private zero-TTL results and current visible-catalog continuation semantics.

Keep reusable behavior within existing Application/Domain ownership. A static provider needs no business Query;
a Query-backed provider retains its own current business admission. Permission tooling is neither a template
engine nor a consumer Prompt implementation, runtime sandbox, relationship policy or source of automatic grants.

### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and side effects |
| --- | --- | --- |
| Integrator associates protected Prompt requirements | N/A; composition | Validate actual definition association/nonempty requirements without building bodies, resolving authority or granting Permissions. |
| Agent lists Prompts | No new business message | Filter current permitted metadata before pagination/disclosure; no provider content work. |
| Agent directly gets a Prompt without listing | No new AccessControl business message | Admit before declared argument validation and selected-provider processing; only that permitted provider runs. |
| An admitted provider needs application data | Existing consumer/shared Query, owned by its handler | Independent target/business admission remains mandatory; Prompt Permission does not grant application scope. |
| Agent later follows a returned Resource/Skill link | Later separately admitted Resource operation | No automatic fetch, target grant, activation or execution; link metadata itself must be recipient-safe. |

Permission checking adds no Command, Domain event, grant, mutation or business commit. Existing authentication nonce
consumption and authority fences remain request-local. Consumer providers are trusted application code, not code
sandboxed by this package; alternate provider/business entry points retain their own protection.

## Acceptance Criteria

- [x] **Validated fail-closed requirements:** Associate actual registered Common Prompt definitions with nonempty
  valid canonical conjunctive requirements. Missing, malformed, conflicting, foreign/unknown or unmapped association
  rejects at the observable static boundary or denies at runtime as appropriate. Every missing-Permission case
  denies; an argument, caller-supplied Permission array or known name cannot provide authority. No duplicate registry.
- [x] **Real list/get and ordering:** Real Common Prompt composition uses actual AccessControl principal/Permission
  resolution, not only Boolean stubs. Listing filters visible metadata before paging and constructs zero bodies.
  An admitted direct get needs no prior listing. Unknown/denied selections preserve Common's safe outcomes, and
  denied requests perform no declared-argument/provider/Query work. Earlier outer-shape validation remains Common-owned.
- [x] **Fresh request and cursor semantics:** Reuse the same trusted request provider rather than replaying a nonce
  per definition. Fresh later list pages/gets observe Agent revocation, credential replacement and Permission
  changes; already resolved ordinary requests retain snapshot semantics. Private zero-TTL results, visible-catalog
  cursors, immutable metadata and earlier successful responses grant no cross-request access or shared cached allow.
- [x] **Static and Query-backed permitted journeys:** Actual Common providers in controlled package fixtures return
  complete admitted static content and Query-backed content. The latter retains independent current business
  admission, including capability-allowed/data-denied cases; no protected data is embedded solely because the caller
  may get a Prompt. No AccessControl production provider, Query duplication or application relationship model is added.
- [x] **Independent linked targets:** Prompt retrieval does not open linked Resource/Skill content or authorize
  later reads. Demonstrate recipient-safe links and subsequent independent Resource denial using the actual Common
  boundary and controlled target-admission fixture. Do not copy Resource binding code or force static Prompt serving
  to wait for TASK-00085/00086. No Skill activation, Tool/model execution, Workflow authority or application mutation.
- [x] **Truthful safe bounded output:** Invalid arguments, unknown/denied selections and policy/provider/operational
  faults preserve Common's actual safe categories, no raw exception/declaration/argument disclosure and no fabricated
  empty/partial success. Complete output and actual central metadata/envelope remain within finite encoded limits;
  registration/listing bounds include concealed definitions without exposing them.
- [x] **Supported dependency and guidance:** Verify implemented/independently accepted/qualified, tagged Common
  Prompt contracts and first sufficient supported minimum, recording exact version/source/lock evidence. Test that
  minimum rather than only a newer checkout. Make only necessary manifest/dependency changes during authorized
  implementation; no guessed future version or dev snapshot passed off as stable. Document chosen association API,
  request/cache semantics, safe failures, independent Query/linked-target admission and consumer qualifications;
  update affected public composition guidance and `CONTEXT.md`.
- [x] **Complete verification and acceptance:** Focused allow/deny/fault/freshness/provider-call/Query/link tests
  cover owned statements exactly; canonical full package gate passes with complete log, actual exit and receipt.
  Independent technical Review and behavioral QA accept the implementation's nonvisual MCP responses/effect evidence.
  Controlled ports/providers do not qualify deployed consumer storage, cryptography, transport or container lifetimes.
