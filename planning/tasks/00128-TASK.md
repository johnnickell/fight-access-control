### Behavior and Validation

- Consume actual supported Common Query/message/handler/bus and registration contracts. Preserve result inference
  through fetch(), QueryMessage creation, withMeta()/mergeMeta() and dispatch(), including interface-typed callers
  and concrete compositions actually supported here. Do not certify only direct handler invocation.
- Replace unchecked owned payload/caller assertions where qualified relationships supply the type. Concrete
  handler inputs/results and registrations must agree without caller casts, suppressions, shadow types, copied
  buses, direct-handler bypass or repeated Action-level instanceof checks masquerading as inference.
- Positive executable static fixtures prove exact result and element types; negative fixtures reject incompatible
  expectations, payload/handler registrations and use after metadata transformation. Expected negative diagnostics
  must be checked, not silently ignored; fixtures fail if an invalid use becomes accepted or a valid use loses precision.
- Prove applicable registration rules, real routing, result and primary-failure propagation separately at runtime,
  with all owned bindings exercised. Distinguish PHP native checks from static generics; do not promise impossible
  native generic enforcement or build a local router to supply missing upstream behavior.
- Preserve message identity, timestamps, metadata and canonical runtime serialization/round trips. Genuinely dynamic
  deserialization remains an explicitly validated boundary, not an unchecked assertion of a concrete decoded type.
  No wire change is required solely for generic annotations and raw secrets remain non-serializable.
- Preserve read-only Query behavior, authorization/concealment, safe output and failure ordering. No mutation,
  business commit, audit insertion or Event dispatch is introduced by type adoption.
