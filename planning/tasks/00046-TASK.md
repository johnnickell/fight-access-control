# Provision an Agent through a recoverable operation

## What to Build

Deliver the complete replacement provisioning service path from authorized request to one atomic issuance outcome
and prepared delivery. The caller retains a scoped operation key and can retry the original request after response
loss without another Agent, secret generation or audit fact. This is slice A of the TASK split John approved on
2026-09-27 under [TICKET-00012](../tickets/00012-TICKET.md), targeting [EPIC-00009](../epics/00009-EPIC.md)'s `v0.5.0`.

Include the Domain operation/request binding and pending-delivery preparation needed by this path, Domain repository
contracts, Application authorization/cipher coordination, safe results, tests and consumer contract documentation.
Do not create a layer-only foundation PR or a parallel identity system. Public names and concrete bounds are design
work inside this slice; record them before acceptance, following the accepted ADR 0004/WF-002 amendments.

## Use Case and Contract

- **Actor/trigger:** an authenticated maintainer requests provision or repeats the same retained key/request.
  Consumer-owned current caller/delegation/destination policy participates in the package-owned transaction on the
  shared connection and holds authority/slot fences through commit; no actor string or cached allow substitutes.
- **Input/validation:** trusted namespace and originating caller type/stable ID scope an opaque operation ID. Package
  canonicalization binds operation kind, normalized name, registered destination identity/revision and every outcome-
  affecting option. No caller-supplied digest, URL/path destination, name-based correlation or secret input is accepted.
- **Effects:** atomically commit Agent, credential identity/revision, authentication envelope, separately integrity-
  bound delivery material, globally unique delivery ID, destination write order, operation/request and safe audit.
  Slot order spans Agents/scopes and shares the destination ownership/reassignment fence. No sink call occurs here.
- **Retry:** authorize the scope before key lookup/existence disclosure. Existing keys use their persisted canonical
  version, including tombstones; equivalent requests resolve, conflicting/unknown-version requests reject without
  generation or mutation. New-key capacity rules do not reject safe resolution of existing keys.
- **Result/events:** confirmed commit returns safe operation metadata; post-commit publication faults add a typed,
  sanitized warning. Pre-commit failure and indeterminate commit remain distinct. Publish the provision fact only
  after confirmed commit; failure-publication faults cannot replace the actual outcome. Retry is not another fact.
  Issuance is not delivery, activation or permission to launch. Query handlers are owned by TASK-00047; same-key
  service resolution belongs here and cannot be deferred to that TASK.

## Design and Acceptance Criteria

All ten criteria were independently accepted on 2026-09-28. `done` records accepted implementation and local
verification, not PR approval, merge, release or consumer qualification.

- [x] Record concrete public request/result and authorization participation contracts, canonical version rules,
      transaction/uniqueness semantics, integrity-bound delivery tuple and slot reservation contract. Define the shared
      lifecycle-cancellation seam with TICKET-00013's requirements without implementing its worker or guessing a sink.
      Repository contracts remain Domain-owned; consumers implement production adapters on the shared connection.
- [x] Document finite input/admission defaults and optional validated overrides, including ranges and relationships
      with recovery. Default-only operation needs no manual setup of limits or extra human approval. Invalid overrides
      reject safely; capacity rejects/defers new work with a clear retryable outcome and no partial issuance while
      retaining authorized same-key resolution and the ability to recover existing operations.
- [x] Normal provision commits exactly one Agent/credential/audit/prepared-delivery outcome. Original response loss
      plus caller/service restart returns the same identities from storage without repeated generation/mutation/audit.
      Canonical equivalents resolve; changed name, kind, destination or other bound options conflict without disclosure.
- [x] Concurrent identical/conflicting requests leave one committed winner; unique/CAS losers roll back then resolve
      or conflict. Equal opaque IDs in different scopes create distinct delivery IDs. Authorized shared-slot
      reassignment advances destination order; unauthorized ownership denies. Assert persisted state, not only calls.
- [x] Wrong namespace/caller, revoked authorization, expired delegation and denied destination reject new work and
      retries without another scope's existence leaking. Delegated callers authenticate as themselves and retain
      original scope. Authority-capability failure and pre-commit audit/encryption/persistence failure roll back all
      Agent/operation/delivery/reservation/audit state. All participating write contracts share the required fences.
- [x] Inject uncertain commit with separately committed and rolled-back outcomes. Return safe indeterminate status,
      then resolve authoritative storage using the same key after restart; never infer rollback from missing events
      or auto-select another key. A rolled-back attempt leaves no partial state and may later issue once under that key.
- [x] Confirmed commit plus success-publication failure returns typed sanitized warning metadata, including when
      failure publication also faults. No committed work is lost or mislabeled rollback. No success fact precedes
      commit; no duplicate audit/fact on retry. Preserve stable fact identity for any supported notification retry.
- [x] The old raw-return provision signature is removed or explicitly rejects; no implicit key/destination/authority
      or raw-return fallback remains. Results, events, audit, serialization, debug and failure diagnostics expose no
      secret, ciphertext, key path, unsafe provider detail or secret-read capability. Existing authentication and
      single-credential invariants remain intact. Revocation and other operations do not inherit D3's warning exception.
- [x] Operation tombstones retain request version/outcome evidence and cannot become fresh issuance after cleanup.
      Prepared work is suitable for authorized discovery; actual no-caller scheduler recovery is proved by TASK-00049
      with TICKET-00013, not claimed by this TASK's prepared-state tests.
- [x] Focused Domain/Application tests and reusable issuance contract fixtures support TICKET-00012 I1–I7 for
      provisioning. Document public composition and the unreleased compatibility implications; update the owning
      TICKET's evidence references without checking off its cross-operation/worker acceptance prematurely.
