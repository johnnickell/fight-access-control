  audit; configured failure cannot downgrade to disabled/no-op storage. Add explicit optional typed actorId where

  resolver, guessed target actor, label parsing or System/Anonymous fallback. Disabled and pure no-change paths gain
  no newly required audit-only input. Enabled work validates attribution before the first mutation needing evidence,
  not necessarily discovery. Existing business-required inputs and entry/target/scope authorization remain intact.
- Explicitly add typed Feature/action/related Permission evidence after authoritative persistence and before the same
  actual mutation transaction/connection commits. Capture unique evidence identity, real message correlation and
  trusted outcome time through the existing Application Clock contract, with cohesive constructor/caller adaptation.
  Feature has no stored timestamp: do not invent one, use message/database insertion time or fabricate a revision.
  Creation records initial revision without a predecessor; removal records authoritative prior state without a successor.
- Keep creation OFF at revision 1, immutable canonical name, atomic ID/name uniqueness and the transaction-duration
  Permission-reference fence. Any existing Permission tier remains eligible; the binding is a reference, not a grant
  or protected-tier promotion restriction. Creation never upserts/resets an existing Feature or creates a Permission.
- Retirement retains exact target/positive expected revision, complete CURRENT discovery and final full-state CAS.
  Candidate absence, partial/wrong-scope/failed scans and malformed declarations do not establish current absence.
  Preserve code/reference guards, broken-binding retirement, atomic reference release and new identity on later
  reprovisioning; no name retargeting, resurrection of prior choices or cross-deployment lock is introduced.
- Audit failure/concurrent loss rolls back staged Feature/reference/evidence changes together, preserving concurrent
  winners and the primary throwable. Preserve uncertain commit and ordinary post-commit publisher/subscriber failure:
  committed evidence survives publication failure; failure notification is not a rollback receipt. Do not extend the
  Agent issuance warning exception or manufacture evidence after commit/retry for previously unaudited history.
- Use bounded action-specific typed/admitted facts, not entities, raw messages/names/plan snapshots, credentials,
  hashes/ciphertext, diagnostics or unnecessary personal data. Any free text requires field-specific safety admission;
  evidence is not automatically public/log data. No returned-Event inspection, UoW decorator, repository interception,
  independent audit transaction, duplicate helper evidence, rejected-attempt store or new success Event is required.
