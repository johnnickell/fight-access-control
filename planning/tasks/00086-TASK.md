# Authorize complete Skills and protected member reads

## What to Build

Complete [TICKET-00026](../tickets/00026-TICKET.md) by binding conjunctive Agent Permissions to whole Skills through
Common's real Skill availability/provider/discovery contracts, composed with [TASK-00085](00085-TASK.md)'s independent
Resource Permission binding. Consumers can safely expose complete permitted Skill entries and selected files
without treating a manifest, immutable digest, historical URI or prior get as continuing authority.

Use the real `McpSkillAvailability`, `McpSkillResources` and shared read-enabled `McpResourceDiscovery` composition.
Define validated requirement association for the actual whole-revision identity/immutable entry contract; do not
assume a Tool metadata object's identity or use a URI prefix to infer ownership/authority. Keep unknown/unmapped
or invalid associations fail closed and reject invalid static composition where observable. All configured
canonical `PermissionName` requirements remain conjunctive direct Agent checks; consumers retain policy/grants.

Common owns complete frontmatter/manifests, revision identities, integrity, member ownership, pagination and byte
serving. AccessControl supplies reusable Permission admission, not another Skill parser/provider, Resource
catalog, storage mechanism or activation runtime. Preserve existing Application/Domain ownership.

### Actors, Triggers and Side Effects

| Actor and trigger | Commands / Queries / Events | Outcome and side effects |
| --- | --- | --- |
| Integrator associates whole-Skill requirements | N/A; composition | Validate identity/nonempty requirements against actual immutable entries without opening files or granting access. |
| Agent lists Skills or gets an exact Skill | No new business message | Check whole-Skill and all applicable member Resource admission before disclosing a complete entry; no partial successful manifest. |
| Agent directly reads a Skill member | Common owns Resource selection/open, not a new AccessControl Query | Apply whole-Skill and selected Resource requirements independently before content opens, without requiring prior listing. |
| Agent follows saved/historical Skill/member identities in a later request | N/A until an admitted selected read | Reevaluate current authority; hashes, links, earlier manifests and cursors confer no access. |

Checks create no grants, mutate no content, execute no scripts/instructions and emit no new Domain events.
Authentication reuses the same request's trusted provider and existing nonce transaction. Any application-backed
content use case retains its independent scope/business Query admission.

## Acceptance Criteria

- [x] **Validated whole-Skill requirements:** Bind nonempty valid canonical Permission requirements to actual
  configured Skill identities/entries, including historical revisions where served. All requirements are
  conjunctive. Missing/malformed/conflicting associations and foreign/unmapped identity cases reject or deny at the
  appropriate static/runtime boundary; neither a generic Resource allow nor a Tool/Prompt grant supplies Skill access.
- [x] **Real complete Skill journeys:** Real Common `skills/list` and `skills/get` compose with actual AccessControl
  principal/Permission resolution and TASK-00085's Resource decision. Whole-Skill denial conceals the entry; denial
  of any required member conceals the complete entry rather than redacting frontmatter/resources into partial
  success. Common's exact shared Resource capability/provider identity and complete catalog integrity remain intact.
- [x] **Independent selected-member admission:** Whole-Skill denial prevents member reads even when the general
  Resource policy permits them. Selected Resource denial prevents its read even when whole-Skill permission holds.
  An otherwise admitted selected member can be read directly without prior Skill listing/get; do not invent an
  all-other-members requirement for an individual file beyond Common's actual contract. Denied paths open/allocate
  no content stream, and permitted text/binary bytes and integrity metadata remain unchanged.
- [x] **Freshness and isolation:** Share the same trusted request-local provider with Resource decisions instead of
  authenticating/replaying a nonce per entry/member. Fresh later requests, pages and saved/historical reads observe
  revocation, rotation and Permission changes; admitted short requests retain documented snapshot semantics.
  Private zero-TTL cache hints, cursor/catalog changes and separate caller contexts cannot retain authority.
- [x] **No concealed metadata or fake success:** Hidden names/frontmatter/manifests/member links/counts/continuation
  context stay out of successful pages, errors and diagnostics. Unknown/inexact aliases and ownership conflicts
  preserve Common's actual rejection/concealment. Policy/provider/operational faults use the safe Common boundary,
  not raw exception messages or fabricated empty/partial success. Complete-entry and encoded serving bounds remain
  intact without opening content merely to evaluate permission.
- [x] **Qualification and documentation:** Verify actual accepted/tagged Skill/Resource contracts and the supported
  minimum using exact version/source/lock evidence; do not infer support from a version label alone. Document
  whole-Skill versus selected-member requirements, historical identities, trusted composition, untrusted content,
  request lifetimes and consumer containment/scope obligations. Update `CONTEXT.md` and affected public guidance.
- [ ] **Complete verification and independent acceptance:** Focused real Common composition tests cover all missing
  Permission permutations, allowed/denied member combinations, malformed association, faults, encoded bounds,
  current-authority changes and zero denied stream allocations. Exact owned statement coverage and canonical full
  gate pass with complete log/exit/receipt; independent technical Review and behavioral QA accept the implementation.
  Port fixtures prove package composition, not deployed consumer storage, client behavior or database/crypto safety.
