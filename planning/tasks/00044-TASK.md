# Enforce tier eligibility on direct Agent assignments

## What to Build

Make direct Agent grant and complete-set replacement accept only authoritative `ADMIN_SAFE` Permissions. Check
the entire desired set, including an unchanged set, and keep tier authority stable through the transaction's Agent
membership write. Remove actor-only Agent Permission authorization dependencies from the three handlers and their
coordinator.

## Use Case and Effects

| Actor and trigger | Commands / queries | Events | Effect and result |
| --- | --- | --- | --- |
| A consumer grants or revokes one direct Agent Permission | `GrantPermissionToAgent`, `RevokePermissionFromAgent`; existing Agent reads | Existing grant/revoke Events on real changes | An `ADMIN_SAFE` grant succeeds; a protected or missing grant fails. Revocation keeps ordinary desired-state behavior. |
| A consumer replaces an Agent's complete Permission set | `ReplaceAgentPermissions`; existing Agent reads | `AgentPermissionsReplaced` only after a real commit | The normalized desired set contains only authoritative `ADMIN_SAFE` Permissions. One protected, missing, malformed, or stale item rejects the entire request without a partial write or success Event. |

## Permissions, Validation, and Compatibility

- The consumer protects every Agent Permission command entry point and decides caller, target, and scope authority.
  Actor IDs remain provenance. The package adds no actor/target authorization port or Permission-name policy.
- Validate tier inside the coordinator's Unit of Work before grant no-op or replacement no-op can return. Preserve
  expected assignment-revision checks, duplicate normalization, exact-definition resolution, and existing no-op
  behavior for eligible sets.
- Strengthen the Agent repository reference contract and package in-memory seam so a concurrent tier promotion
  cannot leave a committed protected Agent membership. TASK-00045 owns end-to-end reconciliation interleaving
  proof; consumer adapters choose locking mechanics.
- Remove `AgentPermissionAdministrationAuthorization` and obsolete supporting doubles/exceptions when unused.
  Preserve safe failure Event, original exception rethrow, transactional rollback, and post-commit success order.
  Record the accepted pre-1.0 constructor change in maintained consumer guidance.
