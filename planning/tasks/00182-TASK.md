# Convert recoverable Agent issuance to Commands and outcome Queries

## What to Build

Implement [TICKET-00053](../tickets/00053-TICKET.md)'s amended caller contract as one coherent PR: move provisioning
and rotation coordination into registered void CommandHandlers, and use authorized outcome Queries rather than
returned issuance/warnings. Commands work whether invoked synchronously or asynchronously, now or after serialized
delay/restart/redelivery. No transport, endpoint, broker or request lifetime is assumed.

### Owned paths and messages

- Replace AgentProvisioningService::provision() and AgentCredentialRotationService::rotate() with secret-free intent
  Commands (proposed names ProvisionAgent and RotateAgentCredential) and corresponding actual Common CommandHandlers.
  Follow the current aggregate-first Architecture/Naming rules and actual candidate homes, not today's broad
  Security/Service directories. Domain owns invariants; Application handlers own coordination and transactions.
- Reuse GetAgentOperation/GetAgentOperationHandler/AgentOperationView through the configured QueryBus for original
  issuance and recorded delivery/credential dispositions. They already expose the safe required data. Extend/add a
  transport-neutral Query only for a demonstrated gap; no duplicate status model or speculative queue-progress API.
- Update every owned registration, caller, fixture/factory, constructor/named caller, serialization test, maintained
  composition/issuance/rotation/recovery/status/integration/evidence guide and applicable breaking-change note.
  Remove superseded direct APIs and unused AgentProvisioningResult/AgentCredentialRotationResult/AgentPublicationWarning
  consumers/types once replaced, without aliases or forwarding facades. Keep AgentIssuance and current persisted safety.
- Reuse existing provisioning/rotation business tests and shared canonical/issuance-recovery/delivery/restoration fixtures.
  Adapt their issuance entry points and expected outcomes once for the pair; do not add a parallel conformance framework.

### Execution, authority and recovery

- Commands round-trip bounded secret-free original scoped key, name or Agent/predecessor/revision, destination binding
  and applicable provenance. Preserve canonical request bytes/marker 2 and immutable message metadata. Operation identity
  is independent of envelope identity; retain the same key/original request before dispatch and across all retries.
- A serialized scope/actor, original provenance or enqueue-time allow is not authority. Consumers authenticate the real
  executing invoker/explicit delegated worker independently; handlers recheck current scope/target/destination and hold
  actual transactional authority/cohort/restoration fences before lookup/work through commit. Do not require live Console,
  HTTP or MCP state, impersonate the originator, substitute SystemId or silently retarget a stale predecessor.
- Preserve expected-state checks, finite limits, contention/collision resolve-only retry, atomic retirement/cancellation
  and successor operation, destination ordering, receipts, tombstones and stale-writer/restoration safety. Delayed,
  duplicate and out-of-order invocation never grants fresh authority or duplicates issuance/evidence/success publication.
- Handler success returns void. Dispatch acceptance is not proof of execution, issuance, delivery, activation or use.
  Safe original issuance/dispositions come from the independent authoritative read-only Query, with current authorization
  before lookup and before disclosure, including absence/terminal records. Queries never generate, commit, publish,
  acknowledge delivery, insert audit or read material; storage failure is unavailable, not absence.
- Query indeterminate covers unknown/not-yet-executed/in-flight/absent committed issuance, not a known rejection or
  rollback. It does not identify queue progress or reconstruct pre-commit exceptions. Keep original-key retry possible
  without new-work capacity gating reads/resolution; never choose a replacement key merely because status is absent.
- Pre-commit failure preserves sanitized primary execution failure and staged rollback. Lost commit acknowledgement
  surfaces safe uncertainty/retryable execution failure, not fictitious success or rollback; prove both possible stored
  outcomes and same-key reconciliation. Async submission is not promised synchronous access to a worker's exception.
- Confirmed commit survives both publishers failing and completes void issuance handling, with existing best-effort
  sanitized failure evidence. No returned publication warning, durable warning store or outbox promise. Preserve separate
  delivery/recovery responsibilities and other operations' own publication/failure policy.
- Preserve the actual applicable audit/provenance contract in the candidate. TASK-00162 owns optional audit/retained-origin
  enhancements; conversion neither duplicates them nor blocks independent audit work. Internal generated secrets remain
  sensitive/non-serializable, absent from Commands, results/status, Events, logs and provider exception chains.
