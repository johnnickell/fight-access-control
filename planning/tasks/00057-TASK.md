## What to Build

Simplify the unreleased Agent operation contract to one supported canonical representation across provision,
rotation, status, delivery and maintenance. Keep the current Unicode-aware normalization introduced as v2: the fixed
edge-whitespace set, UTF-8 validation, nonempty/120-code-point limit, preserved case/internal whitespace and no NFC
conversion. Keep marker `2` as the single supported canonical version; its number does not imply support for `1`.
Storage/destination contract version numbers are separate concepts, not additional canonical versions.

Remove the ASCII-only v1 reader and multi-version creation/reader selection, switch-back, migration and compatibility
machinery that exists only for hypothetical old consumers. Do not preserve old constructors/signatures or introduce
shims solely for backward compatibility. Keep a cohesive Domain owner for the one canonical request rule; use the
same normalized name for binding and newly provisioned Agent state. Reuse existing owning services, not a registry
or second issuance subsystem. Target remains unreleased `v0.5.0` under [TICKET-00014](../tickets/00014-TICKET.md).

## Use Case and Contract

- **Actor/trigger:** a currently authorized caller or delegated worker creates an operation, retries after response
  loss/restart, or reads/reconciles retained current-contract state.
- **Validation:** current scope/target/destination authority precedes lookup/disclosure. Look up retained keys,
  including tombstones, before treating a request as new work. Validate the single supported persisted contract;
  old/unknown/corrupt markers reject, never migrate, reinterpret, become absence or select fallback issuance.
- **Effects:** equivalent retries resolve the original Agent/credential/delivery identity without repeated generation,
  mutation, audit or success fact. Conflicts bind kind, normalized name or rotation target/original predecessor and
  destination identity/revision. Original rotation retries do not reapply a stale predecessor mutation check.
- **New work:** normal atomic issuance, prepared delivery, current-authority and destination-order fences, finite
  admission defaults and post-commit result/event behavior remain intact. No runtime version selection is required.
- **Reads/failures:** status has no commit/events/material access. Unavailable or uncertain state remains distinctly
  unavailable/indeterminate. Issuance does not establish delivery, activation or use permission. Cleanup retains the
  original correlation and terminal evidence; lack of backward compatibility is not permission to reuse issued keys.

## Acceptance Criteria

- [x] **C1 — One best current contract:** retain the existing v2 Unicode-aware semantics as the sole supported rule
      and canonical marker. Provision/rotation binding, Agent name and safe status/OpenAPI agree. Remove v1 support,
      historical-reader dispatch and cross-version creation/switch-back configuration; do not merely hide them behind
      new names. A single persisted marker and fail-closed support check are sufficient; no migration framework.
- [x] **C2 — Same-contract retry/restart:** actual provision and rotation services resolve original requests after
      fresh composition with identical Agent/credential/delivery identities and no duplicate generation, mutation,
      audit or success event. Do not seed old-version outcomes or manufacture another version to demonstrate upgrades.
- [x] **C3 — Equality/conflict:** prove the fixed Unicode edge set and length/encoding rejection, unchanged case and
      internal whitespace, kind, target, original predecessor ID/revision and destination ID/revision binding.
      Equivalent retries stay equivalent; changed inputs conflict; rotation retries do not mutate the predecessor again.
- [x] **C4 — Retention and fail-closed state:** pending, delivered, revoked, superseded, expired and cleaned current
      operations retain their original keys and outcomes. Unsupported markers (including 1), corrupt bindings and
      unavailable storage reject safely without fallback, migration, disclosure, key reuse or successor substitution.
- [x] **C5 — Proportionate admission safety:** simplify canonical creation/reader-set contracts and their consumers
      for one supported contract. Retain TASK-00056's actual composition/capability checks, shared transaction fences,
      monotonic cohort generations and stale delivery/cleanup acknowledgement rejection. Remove upgrade-only API and
      fixture obligations without weakening destination ownership/order, current authority or invalid-state rejection.
- [x] **C6 — Authorization and secret safety:** wrong scope/caller, revoked authority and expired delegation still
      deny retry/status; no raw/ciphertext secret, key path, provider detail or read capability leaks. Preserve atomic
      issuance, safe publication warnings and indeterminate outcomes, and issuance/delivery/activation/use separation.
- [x] **C7 — Meaningful bounded proof:** adapt the public-service/consumer-bindable scenarios to the single contract;
      remove cross-version migration matrices and compatibility-only fixtures/assertions. Preserve useful restart,
      lifecycle, cleanup and safety proof with existing issuance/delivery suites. Default OpenAPI integration and
      exact owned statement coverage still pass; do not keep dead compatibility branches just to retain test counts.
- [ ] **C8 — Aligned guidance:** update public docs, README, CONTEXT, project profile, changelog and affected conformance
      guidance to describe initial adoption of one contract, not obligations to retain nonexistent historical readers.
      Preserve old decisions/review receipts as dated history. No consumer migration/backfill, routine version choice,
      extra approval or promise of backward compatibility is added. Obtain fresh independent acceptance before done.
