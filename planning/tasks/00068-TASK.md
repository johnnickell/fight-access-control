# Remove support for previous package iterations

## What to Build

Apply John's package-wide pre-v1 decision in [ADR 0011](../adr/0011-pre-v1-current-contract-only.md): keep the best
current API and persisted contract, with no extra code supporting earlier iterations. This is a standalone cleanup
across Agent and User credential-delivery boundaries, not another compatibility feature. It precedes TASK-00058 so
restoration work cannot entrench the legacy model. Existing completed TASKs remain historical acceptance records.

## Use Case and Boundaries

Maintainers and integrators use one current contract for provisioning, rotation, revocation, authentication, reads
and credential delivery. Remove obsolete alternatives and update internal callers, fixtures and schemas together.
No new Command, Query, Event, Permission, migration runner or authority system is needed. Current inputs, state
transitions, audit/publication guarantees and caller/target authorization retain their existing owners.

Normal current-contract hydration and state recovery remain necessary. Remove the legacy marker and branches, not
validation of persisted authority or atomic cancellation of delivery. Make current Agent issuance/cancellation
obligations unconditional. User delivery outcomes require explicit claim identity and occurrence time; keep genuine
bounded operational defaults, not historical argument inference.

No preservation/conversion of prior-version data, consumer upgrade, data reset, dependency change, production Adapter,
release, publication or deployment is included. Unknown/corrupt state must not be treated as new issuance. Current
cryptographic envelope/key handling, standard protocol versions and generation/order fences are not obsolete merely
because their names include a version or compatibility term.
