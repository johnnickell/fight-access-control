# Reduce PHPUnit overhead without weakening coverage

## What to Build

Separate discovery, test setup and execution, and coverage overhead before choosing an optimization. Make only changes with equivalent proof and measured benefit; report rejected candidates and any unachieved savings. Keep `./bin/quality` as the single authoritative fail-fast gate, invoked by `./bin/build` locally and by the hosted workflow in its prepared environment.

## Work evidence

Use a smaller bcrypt work factor only in the test password collaborator and selected authentication and recovery fixtures. The fixtures still create freshly salted hashes and exercise real password verification, including rejection and verified rehash paths. No production work factor, test assertion, test classification, OpenAPI check or gate command changed.

Local discovery and XML output took 14.7s. All 10,273 cases without coverage took 8:06 wall time, with a 7:59 PHPUnit timer and 6:39 summed case time including setup and teardown. A qualifying baseline build recorded a 13:47 PHPUnit timer with coverage. The roughly 5:48 difference is an overhead estimate, not an isolated instrumented measurement. Expensive password setup stood out even without coverage. A matched focused sample fell from 3:17 to 0:09 wall time (172 cases and 2,313 assertions on each side). Keep independent discovery and coverage attribution; dropping coverage, deleting tests or changing sleep/transport setup was not adopted.

The fresh candidate build passed with the same 10,273 expanded cases (9,419 Unit, 847 Integration, 7 Functional, including 220 OpenAPI cases), zero failures or skips, and identical statement and Unit-only totals of 11,959/11,959 over 558 files. Local shared-gate time was 19:10 versus an earlier 21:39 (11.5% lower); the candidate build updated one dependency and run conditions were not matched, so this is descriptive only.

The [baseline Tests run](https://github.com/johnnickell/fight-access-control/actions/runs/44872281683) and the [first candidate Tests run](https://github.com/johnnickell/fight-access-control/actions/runs/44932596622) both passed. These results do not establish a hosted speedup or whether the full gate met the 15% target.

The maintainer approved dropping the original requirement for three matched hosted runs per side after Review identified it as the only blocker. The change is limited to the evidence requirement: the speedup, coverage safeguards and independent Review and QA obligations remain.
