# Reduce PHPUnit overhead without weakening coverage

## What to Build

Use the [WF-037 baseline](../wayfinder/research/WF-037-quality-gate-baseline.md) to prioritize coverage-enabled PHPUnit. Separate discovery, test setup and execution, and coverage overhead before choosing an optimization. Make only changes with equivalent proof and measured benefit; report rejected candidates and any unachieved savings. Keep `./bin/quality` as the single authoritative fail-fast gate, invoked by `./bin/build` locally and by the hosted workflow in its prepared environment.

## Acceptance Criteria

- [ ] Compare at least three matched hosted runs per side, with the same runner class and resolved dependencies. Record tested revisions, phase timings, cache state and median shared-gate wall time. Isolate [fixture relocation](../tickets/00056-TICKET.md), [tooling ports](../tickets/00057-TICKET.md) and [timing-sensitive test changes](00194-TASK.md) from the comparison. Keep local and hosted timings separate; if hosted measurement is unavailable, record what is missing rather than claiming a hosted result.
- [ ] Preserve the exact statement denominator and verdict, independent Unit-only line attribution and verdict, shipped OpenAPI checks, and unique behavior proof. No test deletion without documented equivalent proof, no new skips or retries, and no alternate completion gate. Profiling variants are not substitutes for the canonical run.
- [ ] Report the result against the provisional 15% median improvement target. The target is not a release gate. No application commands, queries, events, permission or persistence changes.

## Verification

Select the worktree before implementation. Retain the timing comparison, coverage outputs and full canonical `./bin/build` receipt for any adopted changes. Compare test counts, failures and skips; qualify changes to coverage or gate tooling directly. Record planning, documentation-link and diff checks.
