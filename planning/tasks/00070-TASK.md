# Provide minimal Agent profile reads and managed Permission definitions

## What to Build

Deliver the framework-neutral, read-only profile path and managed Permission contract for
[TICKET-00019](../tickets/00019-TICKET.md), independently of Fight Common's Tool API. Add a minimal
Agent profile query and immutable result returning exactly `{agent_id, name}` from a fresh authoritative Agent
lookup. Do not use or serialize the administrative `AgentView`, cache a principal's name, resolve assigned
Permissions, or expose credential, state or revision fields. An absent or revoked current target is generically
unavailable. Reads do not mutate, commit or emit success events. This query may accept a target `AgentId` as an
internal reusable Application input; [TASK-00071](00071-TASK.md) must bind it exclusively to the current
principal's ID at the tool boundary. Neither this query nor an Agent ID supplied to it authorizes the caller.

Provide reusable managed `AGENT_PROFILE_READ` and `AGENT_PROFILE_UPDATE` definitions, each `ADMIN_SAFE`, with no
automatic assignment. Consumer-owned stable `PermissionId` values are supplied to the existing managed-policy
contract: each consumer generates its two distinct IDs once using Fight Common `Uuid::comb()`, fixes them in its
seed/migration, and never regenerates them on startup or reconciliation. Do not hard-code package UUIDs, create
Permissions as a side effect of a read, or implement a consumer migration/grant. Keep the smallest public surface
consistent with current managed-policy conventions and document how a consumer declares and seeds both identities.
The MCP metadata and actual Permission enforcement belong to TASK-00071/TASK-00035, not this query.
