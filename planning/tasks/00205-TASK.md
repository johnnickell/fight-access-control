# Enforce the TokenSet credential handling contract

## What to Build

Enforce the [documented browser authentication contract](../../docs/openapi-composition.md) on the returned [TokenSet](../../src/Application/AccessControl/User/Security/TokenSet.php). It carries an access token and refresh credential for explicit delivery. Follow the package's existing [credential-material safeguards](../../src/Domain/AccessControl/CredentialDelivery/EncryptedCredentialMaterial.php) where applicable.

## Acceptance Criteria

- [x] Native serialization of the whole result is refused. The refusal and ordinary debug output expose neither credential. Verify with synthetic values.
- [x] Consumers can still obtain the intended values through explicit getters. Check the existing browser-cookie and opt-in portable response paths, including which credentials each response may carry. Preserve authentication, refresh, expiry and persistence contracts.
- [x] Compare the latest published Access Control release with develop. Recommend to John whether an earlier patch is warranted, naming the affected release, proposed version and compatibility considerations. Record any consumer evidence still outstanding.
- [x] Keep the change within Access Control. No new permissions, commands, events, storage migration or dependency on Common 2.0 is required.

## Verification

Start with focused coverage of the promised behavior. Exercise existing authentication response tests and run the full project build. Record candidate revision, results and independent review and QA. Mathias returns the patch recommendation before any tag.

passed (254 tests, 4,893 assertions). The browser body rejects refresh credentials; the explicit portable body
requires one. The actual browser cookie remains consumer-owned. The canonical Work handoff maps the original
