# Enforce the TokenSet credential handling contract

## What to Build

Enforce the [documented browser authentication contract](../../docs/openapi-composition.md) on the returned [TokenSet](../../src/Application/AccessControl/User/Security/TokenSet.php). It carries an access token and refresh credential for explicit delivery. Follow the package's existing [credential-material safeguards](../../src/Domain/AccessControl/CredentialDelivery/EncryptedCredentialMaterial.php) where applicable.

## Acceptance Criteria

- [ ] Native serialization of the whole result is refused. The refusal and ordinary debug output expose neither credential. Verify with synthetic values.
- [ ] Consumers can still obtain the intended values through explicit getters. Check the existing browser-cookie and opt-in portable response paths, including which credentials each response may carry. Preserve authentication, refresh, expiry and persistence contracts.
- [ ] Compare the latest published Access Control release with develop. Recommend to John whether an earlier patch is warranted, naming the affected release, proposed version and compatibility considerations. Record any consumer evidence still outstanding.
- [ ] Keep the change within Access Control. No new permissions, commands, events, storage migration or dependency on Common 2.0 is required.

## Verification

Start with focused coverage of the promised behavior. Exercise existing authentication response tests and run the full project build. Record candidate revision, results and independent review and QA. Mathias returns the patch recommendation before any tag.

## Work evidence

`TokenSet` refuses native serialization and redacts both credentials in ordinary PHP debug output. Its getters
and the browser and portable response schemas are unchanged. The synthetic regression first failed because native
serialization succeeded. After the fix, the focused TokenSet, authentication, session-lifecycle and OpenAPI checks
passed (254 tests, 4,893 assertions). The browser body rejects refresh credentials; the explicit portable body
requires one. The actual browser cookie remains consumer-owned. The canonical Work handoff records the full-gate
result and maps the tested snapshot to the committed candidate. Independent Review and QA remain pending.

### Release recommendation for John

Ship a focused `v0.11.1` patch from the published `v0.11.0` line after independent acceptance and separate release
approval, rather than waiting for or taking all of `develop`. GitHub and Packagist identify `v0.11.0` at
`6258682512e2c8d76a3fa655dd633167bd8f55b6`. Its `TokenSet` is identical to the pre-fix `develop` class even though
the release guide already says it is non-serializable. `develop` contains unrelated tooling, documentation and

response schemas, PHP or Common requirements, or persisted session data. Callers relying on unsupported whole-object
serialization will now receive `LogicException`; callers relying on raw object dumps will see redacted credentials.

Consumer evidence remains outstanding: check actual auth response builders, cookie attributes and delivery, explicit

do not establish deployment exposure or that any real credentials were disclosed.
