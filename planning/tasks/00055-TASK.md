# Preserve existing Agent authority through upgrade

## What to Build

Deliver explicit legacy/non-recoverable representation and compatibility behavior for existing Agents without
manufacturing operation history or changing authentication authority. A known active legacy Agent gains recoverable
issuance only through an explicitly authorized new rotation. This is slice A approved on 2026-09-27 under
[TICKET-00014](../tickets/00014-TICKET.md), targeting [EPIC-00009](../epics/00009-EPIC.md)'s `v0.5.0`.

Include Domain/read-contract changes and Application integration as necessary, behavioral compatibility fixtures,
focused tests and the existing-data/API section of migration guidance. Consumer adapters own actual row/schema
conversion; there is no package migration Command or production Adapter layer.

## Use Case and Contract

- **Actor/trigger:** a consumer maintainer upgrades existing data/composition; an authorized caller inspects a legacy
  Agent or explicitly rotates its known current credential using the replacement public service.
- **Validation/permissions:** current caller/target/destination authority remains mandatory. Legacy/non-recoverable
  describes missing historical correlation, not permission to bypass authorization, guess an operation key or disclose
  another scope. Reject invalid/inconsistent historical state rather than infer unavailable facts.
- **Reads/effects:** safe Agent/status reads distinguish legacy state from a committed recoverable operation. Reads
  do not mutate, commit or emit events. Upgrade alone preserves identity, credential/revision and authentication
  envelope, creating no operation, delivery, receipt or issuance/audit fact. Explicit rotation uses TASK-00048's normal
  fenced transaction and safe result; this TASK does not implement another rotation path.
- **Events/failures:** no new migration event; ordinary rotation facts follow its committed outcome. Ambiguous prior
  provision requires reconciliation, never automatic provision. Revoked Agents remain terminal.

## Acceptance Criteria

- [ ] Define/document explicit safe legacy/non-recoverable representation and reconstitution obligations without
      fabricated correlation. A version/data marker is not an asserted issuance or delivery outcome.
- [ ] Behavioral tests reconstitute representative pre-replacement active and revoked Agents and exercise actual
      package authentication/status paths. Identity, current credential, revision, envelope and Permission authority
      remain preserved; active authentication succeeds and revoked authentication remains denied. Upgrade performs no
      generation, rotation, material copying, redelivery or new operation/audit publication.
- [ ] Never backfill operation/request/delivery/receipt bindings from names or audit; an authentication envelope cannot
      become delivery ciphertext. Missing correlation cannot be resolved as an existing recoverable operation.
- [ ] A currently authorized explicit new rotation of a known active legacy Agent creates exactly the new operation's
      recovery binding, retires its predecessor immediately and preserves original legacy meaning. Denied/stale/invalid
      attempts do not mutate; ambiguous provision cannot silently create another Agent; revoked Agents cannot revive.
- [ ] Test legacy raw-return calls remain removed/rejected, without inventing keys/destinations/authority. Runtime
      enforcement remains owned by TASK-00046/00048/00050; return any demonstrated gap to its owner rather than add a
      compatibility escape path. Preserve authentication nonce/current-authority fencing and terminal revocation.
- [ ] Safe results, serialization/debug, audit/events and failures expose no raw/ciphertext credential, key path,
      unsafe provider diagnostic or secret-read capability. Neither legacy status nor new issuance establishes delivery,
      enrollment activation or permission to launch/sign.
- [ ] M1 evidence covers the observable existing-data/API route, not inspection of migration-file text. Document data
      preservation, rejected historical inference and explicit rotation/reconciliation guidance beside the implemented
