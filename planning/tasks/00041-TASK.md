# Classify every Permission with a non-null tier

## What to Build

Make `Permission` and its safe administrative read result expose one non-null `PermissionTier`. A custom Permission
starts `ADMIN_SAFE` and cannot be made protected through its runtime-owned API; managed definitions keep their
consumer-declared tier. Update affected package fixtures and in-memory repositories. This is the shared contract
needed by the custom-Role and Agent assignment TASKs.

## Use Case and Effects

| Actor and trigger | Commands / queries | Events | Effect and result |
| --- | --- | --- | --- |
| A consumer defines a custom Permission | Existing Domain `Permission::define` API; no Command or Query | N/A | New custom authority has explicit `ADMIN_SAFE` tier and stable existing identity/name/timestamps. |
| A consumer reconciles a managed Permission definition | Existing `ReconcileManagedPolicy` path | Existing managed-policy Event after commit | The managed Permission retains the exact declared `ADMIN_SAFE` or `SUPER_ADMIN_ONLY` tier; this TASK does not decide membership. |
| An administrator reads a Permission | `GetPermissionById`, `ListPermissions`, `PermissionView` | N/A | Aggregate and safe result expose the same non-null tier and existing managed flag. |

## Permissions, Validation, and Compatibility

- Tier eligibility does not authorize a caller. The application builder protects command entry points; this TASK
  adds no actor or target authorization port.
- Invalid or unexpected null-tier reconstruction fails closed. No custom API may create or reclassify a
  `SUPER_ADMIN_ONLY` Permission. Managed classification remains consumer-owned.
- Update public aggregate/read signatures and serialization consistently, including any maintained documentation
  and tests. This is a breaking pre-1.0 package contract for consumer persistence and projections; Fight Agent OS
  has no stored Permissions to migrate. Consumer schema/adapters are outside this TASK.
- Preserve existing identity, uniqueness, timestamps, read-query purity, and managed reconciliation behavior.

## Acceptance Criteria

- [ ] Custom Permission creation produces `ADMIN_SAFE`; managed construction/reconciliation retains its declared
      non-null tier; malformed null authority cannot be silently read as eligible.
- [ ] `Permission`, `PermissionView`, `GetPermissionById`, and `ListPermissions` expose consistent non-null tier
      contracts and canonical safe array values; package fixtures and in-memory repositories follow the contract.
- [ ] Focused Domain and query tests prove custom/managed tiers and rejection of invalid reconstruction without
      changing unrelated Permission behavior.
- [ ] Consumer-facing migration notes explain the non-null contract without claiming Agent OS schema adoption or a
      package release.
