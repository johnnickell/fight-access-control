# Read Agent operation outcomes safely

## What to Build

Deliver authorized secret-free operation status queries for the originating caller and an explicitly delegated
worker. Return the original issuance identity/outcome separately from current delivery and credential disposition,
without mutation or implied delivery/activation/launch permission. This is slice B approved on 2026-09-27 under
[TICKET-00012](../tickets/00012-TICKET.md), for [EPIC-00009](../epics/00009-EPIC.md)'s `v0.5.0` replacement.

Use [TASK-00046](00046-TASK.md)'s persisted scope/request/outcome contract and current-authority rules. Add the public
Query/result, Domain read contract as needed, Application QueryHandler and behavioral tests. Same-key issuance retry
is already owned by TASK-00046/TASK-00048; this is not a second issuance workflow or a general credential query.

## Use Case and Contract

- **Actor/trigger:** an originating caller checks a lost response or current status; a worker authenticates as itself
  with explicit current delegation for the original scope. IDs are identifiers, not authentication capabilities.
- **Validation/permissions:** validate bounded identifiers and trusted namespace/caller scope, then enforce current
  caller/delegation/target/destination authority before exposing status, conflicts or existence. A claimed actor string
  or operation ID alone never qualifies. Reuse the approved public authorization/read seam, not copied consumer policy.
- **Outcome:** safe operation identity, original Agent/credential ID/revision and issuance outcome, plus separate
  pending/delivered/superseded/revoked/expired/retryable/terminal delivery disposition as recorded. Storage uncertainty
  is a distinct safe outcome, not absence treated as permission to issue again.
- **Side effects/events:** N/A by design. A QueryHandler does not generate credentials, materialize secrets, alter
  lifecycle/delivery, acknowledge work, commit a Unit of Work or emit Domain events. Delivery workers and any admission
  transaction remain TICKET-00013's command/service responsibility.

## Acceptance Criteria

- [ ] Query DTOs/read results follow package immutable safe serialization and required-data validation conventions;
      handlers use Domain repositories and public handler registration contracts. Concrete shapes and failure
      classifications are documented with TASK-00046's outcome representation, not a transport response envelope.
- [ ] Originating caller and currently delegated worker read the same original committed identity with separately
      accurate current disposition. A worker authenticates as itself and does not rewrite the original caller scope.
      Wrong caller/namespace, revoked authority, expired delegation and denied destination disclose no other-scope
      existence or state. Equivalent checks apply even when a requested outcome is already terminal.
- [ ] Original issuance remains identifiable after supersession/revocation/expiry; it never becomes a successor's
      credential or secret. Cover pending, delivered, retired, retryable key/storage failure, terminal failure and
      indeterminate cases using persisted contract states. Do not fabricate a delivery success from issuance metadata.
- [ ] Read a retained/tombstoned key under its recorded request version. Historical meaning remains stable; unsupported
      versions deny safely without choosing today's canonicalizer or falling through to new issuance. No read changes
      the stored binding or produces a new operation key.
- [ ] After response loss/restart, safe lookup resolves authoritative stored outcome without repeating mutation/audit.
      Distinguish an unknown/indeterminate outcome from confirmed commit and known pre-commit failure without guessing
      based on missing events. Connection recovery uses the same original key through the owning service when needed.
- [ ] New-work capacity exhaustion does not gate authorized status lookup or same-key recovery; invalid optional
      overrides cannot disable bounds. Storage outage remains honestly unavailable/indeterminate, not fabricated state.
- [ ] No raw secret, ciphertext, secret digest, key path, provider exception detail or decryption/read handle appears
      in returned/serialized/debug/failure state. A publication warning cannot be treated as delivery proof. Neither
      status nor a receipt provides current authorization for enrollment activation, launch or signing.
- [ ] Query tests assert no aggregate mutation, credential generation, commit or event and cover denied/invalid/missing
      inputs and safe failure behavior. Persisted fixtures prove all states before worker integration; label them as
      such. TASK-00049 later proves real package provision/rotation-to-worker status transitions, not consumer adoption.
- [ ] Update public query/composition guidance and TICKET-00012 I1/I5/I6/I7 evidence references. Tests remain owned by
      this read path rather than deferred to the conformance TASK.
