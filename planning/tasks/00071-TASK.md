# Bind protected self-service Agent profile tools

## What to Build

Deliver the two package-owned MCP tools for [TICKET-00019](../tickets/00019-TICKET.md) using the installed and inspected
Fight Common v1.3.0 Tool API. Bind both declarations to
[TASK-00035](00035-TASK.md)'s Agent-aware requirement metadata/availability boundary and the distinct managed
`AGENT_PROFILE_READ` and `AGENT_PROFILE_UPDATE` Permissions from [TASK-00070](00070-TASK.md). A denied or unresolved
Agent remains unknown/unavailable under Common's neutral decision **before** Tool validation, query/command
dispatch, progress or protected diagnostics. Do not duplicate Common naming, discovery, invocation, retry or wire
error mechanics; reuse TASK-00035's request-local principal and conformance evidence.

The read tool accepts no target input and queries TASK-00070's fresh minimal profile with only the authenticated
Agent principal's ID. Return exactly structured `{agent_id, name}` using Common's standard `McpToolOutput`, with
its derived JSON text and no separately authored success sentence. The update tool accepts only the new name
(no caller-supplied Agent ID or other authority
field), dispatches [TASK-00069](00069-TASK.md)'s generic `UpdateAgent` with the authenticated Agent as **both**
target and typed initiator. Normalize the input through `AgentName::fromString()`, execute the command synchronously
through Common's void CommandBus, then acknowledge exactly structured `{agent_id, name}` from that target and normalized
input only when dispatch succeeds. Real changes and no-ops have the same acknowledgement. Use Common's derived JSON
text for that same structured value; no separate changed/no-op sentence or `changed` field. No handler/bus return,
compensating read, second update path, tool-specific success fact or authorization inference from typed initiator
identity. The acknowledgement describes the successful request, not the latest name after a competing rename.

Invalid names fail validation without a write; a missing/revoked target is generically unavailable. Sanitize
errors: no credential, assigned Permission, storage diagnostic, stack detail or false rollback claim. Preserve the
uncertainty after a successful commit followed by event-publication failure: the tool reports failure without
promising the rename did not occur or that a retry will succeed. Exact wire representations follow the inspected
published Common API; WF-008 concealment remains distinct from post-authorization operation failures.
