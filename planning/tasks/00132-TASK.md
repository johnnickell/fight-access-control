## What to Build

ResultSet/collection guarantees, then enforce AccessControl request-specific metadata, elements and promised scope.
Do not create a shadow ResultSet or duplicate universal invariants in every handler. Authorized callers request
one page; session callers use existing self-service or admitted cross-user administration, not authority inferred
from pagination or supplied target IDs. Entry adapters retain their existing authentication/authorization duties.

### Complete Paths

handlers, result mappings and directly necessary repository/caller/fixture/example changes. Refresh the six-handler
manifest against the actual candidate; account for moved/new/removed declarations and follow implemented architecture.

- Return exact typed ResultSets of safe User/Role/Permission/Agent/Feature/session Views and authoritative applicable
  revisions. Check request/result page and page-size agreement, bounded records and promised filters/order/scope.
- For active sessions preserve self-service/cross-user administration admission before work. Reject results belonging
  to another User or violating the promised usability/expiry predicate at the admitted read time; preserve safe
  current-session marking without introducing a new permission or lifecycle transition.
- Retain exact Agent Permission snapshot resolution and Feature missing-binding information. A wrong related identity
  is not an absent resource; do not disclose unrelated rows or fabricate an empty page after a failed dependency.

### Common and Application Ownership

- Common v1.5.0 supplies `ResultSet::strict(int $page, int $perPage, int $totalRecords, ArrayList $records): self`
  on the existing generic ResultSet. Adopt this construction path rather than duplicate its universal numeric/count
  checks in handlers: page and size are positive, total is nonnegative, and count cannot exceed size or total.
  Positive totals use exact integer ceiling division; zero total reports one page. Invalid local tuples throw
  Common DomainException, not a safe not-found/empty response. Exact View elements remain AccessControl-owned.
- Validation is construction-only. The legacy constructor stays permissive and both paths expose the same mutable
  ArrayList; ResultSet's native type does not prove strict construction or continuing validity. Use the supported
  strict boundary for received/mapped results and account for mutation before disclosure, without a shadow DTO,
  per-handler copies of universal validation, invented validation provenance or an immutable-snapshot claim.
- AccessControl owns the relation to this request: requested page/size, target User, admitted read time and other
  promised filters/scope. Admit these explicitly instead of trusting any correctly typed ResultSet as request-correct.
- State valid empty and out-of-range page semantics under the actual repository contract. Page beyond totalPages
  is not automatically invalid. Do not infer count/row cross-read atomicity or add a write transaction/lock merely
  to make metadata appear stronger than the persistence promise.
- Reject inconsistent or excessive results rather than silently truncate a faulty page, normalize bad metadata or
  relabel internal/provider failure as not-found/empty success. Preserve intentional Application categories and
  Domain/Application direction; do not repeat checks already guaranteed by native declarations.
- Align necessary callers/current examples and relevant existing safe-error composition. Queries remain read-only,
  with no aggregate mutation, commit, audit write, lifecycle cleanup or Event dispatch.
