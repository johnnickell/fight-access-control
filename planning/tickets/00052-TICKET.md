# Qualify independent and combined admission

## Problem and Outcome

Under [EPIC-00018](../epics/00018-EPIC.md), separately passing Feature and Permission checks do not automatically
qualify their native composition or independent installation. Maintain a complete capability-selection/cross-framework
evidence map, reconcile integrated behavior and publish accurate current composition guidance with real consumer
limits. Reuse supplier unit/integration tests and acceptance evidence; this is targeted gap closure, not a second
testing programme or a test-later substitute for each supplier's complete acceptance.

## Use Cases and Contracts

| Actor and trigger | Observable outcome |
| --- | --- |
| Integrator selects Feature-only or Permission-only support | Only selected capability/dependencies are activated; no accidental dependency on the other policy/runtime path. |
| Both capabilities protect the same native action | All effective requirements apply before protected work; neither gate overwrites metadata/context or grants the other. |
| Class/method/route hierarchy combines with mixed Feature states | Inherited conjunction and conflict rejection remain the same across all five frameworks. |
| A reused/nested request or native fault crosses composition | Correct action/authority lifetime, response short-circuit, safe refusal/fault classification and one reporting owner. |
| Consumer follows documented installation/adoption guidance | Supported APIs/minima, order/coverage limits and remaining real-runtime qualification are explicit, not universal guarantees. |

Checking/merging/admission creates no business Command, Query, Domain Event or mutation audit evidence. Preserve only
already required authentication effects, without adding a second authentication pass or replaying Agent nonces.

  Reuse adequate unit/native evidence for class/method/ancestor/override/route additions, repeated/duplicate requirements,

  authenticated/protected modes. No copied merger/policy or fixture-only alternate implementation may stand in for actual owned paths.
- Qualify Feature-only without Permission middleware, Permission-only without Feature evaluation, and both together.
  Feature absence is not public Permission access, PUBLIC Permission policy may have a Feature gate, and Feature ON
  cannot bypass authentication/action authorization. Preserve User/Agent distinctions and deliberate anonymous Feature
  context, not invalid-context fallback or silent weakening of an inherited requirement.
- Verify OFF/unmet PREVIEW generic 404 separately from missing/broken definitions/configuration/storage/provider faults,

  ordinary denial, expose Feature/configuration/credentials or silently admit after either capability fails.
- Establish actual native route/validation/action order, supported construction limits, response short-circuit, sequential/
  nested/subrequest/reused-container lifetime and exception paths. Check one trusted current authority path, no stale
  targets/providers, inherited context leak, extra authentication or replayed nonce. Admission is no live/background lease.
- Qualify selected native/Common type-based error/report/render/header/negotiation/fallback composition with one redacted

- Prove optional dependency isolation and actual tagged/sufficient-minimum/ordinary Common/framework lanes; record exact
  source/dependency/runtime/candidate identities. Coverage of one PSR-15 framework does not qualify the other. No guessed
  APIs/versions or real-consumer success is inferred from package/native fixture passes.
- Reconcile current docs/examples/Unreleased obligations and explicit selection/registration. Document class/method/
  inheritance/route semantics, invalid configuration, safe failures, freshness/lifetime/order/controller limits,

  installed routes/sinks/proxies and runtime duties. No automatic Agent OS Attribute replacement or sibling repair.
- Each supplier retains its complete callers/tests/docs/full gate/independent acceptance. Route a discovered source
  correction to its requirement owner, integrate its accepted fix and rerun affected composition; do not bury repair
  in a report or defer supplier tests until final conformance. Final completion needs complete current
  candidate-compatible evidence, not sampled, stale, pending or merely historical acceptance.
