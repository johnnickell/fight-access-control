# Library-wide Typing and Handler Failure Contracts

## Destination

Make typing correct and enforceable across the entire AccessControl library, not only selected lookup handlers.
Audit every production declaration and its actual use, correct discovered contract gaps, and prove that callers
receive the declared result or an intentional, correctly classified failure. An audit report alone does not
complete this destination.

John approved the library-wide scope, Common ownership boundary, required-versus-optional lookup policy and
failure semantics during Grill, then confirmed this destination. Grill approved one EPIC only; John subsequently
approved the complete six-TICKET requirement split and TASK plans for all six TICKETs, TICKET-00037–00042
(six/three/five/ten/four/three slices, 31 TASKs). Planning is complete for this EPIC's accepted split, not implementation
or supplier qualification. Separate audit planning and the amended Agent conversion plan are now written; their
implementation and actual supplier qualification remain unfinished.

## Accepted Decisions

### D1 — Exhaustive library coverage

Audit all production Domain, Application and Adapter code, including every CommandHandler, QueryHandler and
synchronous service. Include supporting aggregates, identities, value objects, repository interfaces, service
ports, specifications, Commands, Queries, Events, views/results, exceptions, collections, callbacks and
serialization/hydration boundaries. Include shipped OpenAPI metadata where it declares those contracts.

The bounded planning inventory at `31a5fb02feaf8a55802cd6364ff0ac27b6091d67` contains 447 production PHP files
under `src`: 291 Domain, 154 Application and 2 Adapter, including 37 command handlers and 22 query handlers.
These counts establish breadth, not completed review. Re-enumerate the actual implementation candidate and
account for additions, moves and removals; no handler family or production boundary may disappear through sampling.

Maintain a complete audit inventory with each owned declaration/boundary's disposition, findings, correction or
justified unchanged contract, affected callers and verification. Tests, fixtures and current integration examples
must agree with the resulting production contracts. Distinguish package evidence from actual consumer qualification.

### D2 — End-to-end type relationships

Verify native parameter/property/return types and richer static contracts, including collection element types,
array shapes, nullable/union results, callbacks, message payloads and round-trip serialization. Prefer real domain
values and precise types over ambiguous scalars, unqualified arrays or `mixed` where the contract is actually known.
Retain genuinely dynamic boundaries only with explicit ownership, validation and justification.

Trace each Command/Query through registration, message construction/payload extraction, handlers, configured buses
and its caller. Query-result inference must survive both direct queries and message dispatch. Common owns the
upstream Query/QueryMessage/QueryHandler/QueryBus generic relationships and corresponding command-payload contracts;
AccessControl consumes qualified APIs rather than copying a bus or bypassing dispatch. Local unchecked `@var`
assertions, casts, new ignores or repeated Action-level `instanceof` checks do not establish that relationship.

John explicitly clarified the local transaction-result case during TICKET-00040 planning: native
commitTransactional() remains mixed. A matching local @var is sufficient for the known result returned by the
handler/use case's owned callback, including an accurately described tuple/union where applicable. This records
locally known behavior, not an unchecked cast over unrelated external data. No generic Common UoW API, supplier
qualification task, replacement wrapper/result DTO or redundant runtime result check is required. Do not reopen
that removed hold under callback/enforcement wording. This does not establish bus/Event payload inference or
remove validation/ownership of genuinely dynamic external boundaries.

Native/runtime and PHPStan guarantees are distinct. Prove correct inference and rejection of incorrect use with
static-analysis fixtures, and prove applicable runtime dispatch/registration/result behavior separately. Successful
commands remain `void`; do not invent result DTOs solely for uniformity. John explicitly amended future Agent
provisioning/rotation to void Commands plus independent outcome Queries, with no transport or execution-mode assumption.
Current direct-service results remain baseline evidence until conversion; follow the coordinated amendment below.

### D3 — Required lookup versus intentional absence

Domain repository `getById()` returns its declared aggregate or `null`. Keep nullable repository semantics; absence
alone does not require persistence adapters to throw or a repository method rename.

A required single-resource query returns the expected non-null view/result or throws the appropriate Common
Application failure, normally `ResourceNotFound` for intentional missing-resource intent. Apply the same explicit
absence decision to command handlers without changing valid idempotent/no-op behavior. Audit all existing nullable
query callers, catches, tests and examples before releasing the breaking contract; document external consumer
changes without editing consumer repositories.

Optional discovery/status use cases may model meaningful absence as an explicit typed result/state. Do not retain
unexplained nullable Views or turn meaningful indeterminate Agent-operation outcomes into fictitious not-found
failures. Preserve anti-enumeration, concealment, authorization ordering and secret-free result guarantees.

A repository returning the wrong identity or violating a declared result contract is an internal fault, not an
absent resource. Enforce identity/correlation consistency where owned, without rechecking types already guaranteed
by native declarations merely to move defensive code between layers.

### D4 — Typed results and consistency belong with their owner

Handlers own checks relating repository output to a particular request: exact requested identity/correlation,
requested pagination metadata, page-size bounds and other promised filters or scope. Reject inconsistent results
rather than silently returning unrelated records, truncating a faulty page or relabeling a failure as empty success.

Common owns universal ResultSet/collection invariants and element-type contracts; identify and coordinate missing
upstream guarantees there. AccessControl owns use-case-specific checks, not a shadow ResultSet implementation.
Define valid empty/out-of-range page behavior and total-count consistency against the actual repository snapshot
contract; do not invent stronger cross-read atomicity guarantees than the persistence contract supplies.

### D5 — Failure intent stays transport-neutral and layer-safe

Use Common's qualified Application failure vocabulary for intentional Application outcomes: missing resources,
authentication/permission rejection, state conflict, failed precondition, unusable input, business-rule rejection,
gone resources, rate limits and temporary unavailability as applicable. Preserve structured validation rather than
replacing its field-error contract. Distinguish an explicit failed caller precondition from ordinary state conflict.

Separate internal identity/result violations, programmer faults and unknown infrastructure failures from expected
business rejection. An internal contract failure remains a safe server failure, never a fabricated 404/409/422.
Do not infer exception intent from diagnostic messages or integer codes, and do not blanket-wrap unknown faults as
expected failures. No additional Common exception class is assumed necessary without a demonstrated missing intent.

Preserve `Adapter → Application → Domain`. Domain-owned exceptions remain in Domain and must not extend or import
Common Application exceptions. Application translates known Domain outcomes where appropriate, with specific
package Application subtypes only where useful. Reconcile the local Architecture standard's older LookupException
recommendation for these adopted contracts: generic LookupException is not an automatic HTTP not-found category.
No dependency-rule relaxation or dependency on Agent OS's application failure types is permitted.

HTTP adapters/composition translate deliberate Application categories through Common's opt-in safe error path,
using public constants/projections rather than private messages, codes, causes or traces. Verify relevant 404,
conflict/precondition, rule-rejection and internal-failure mappings. MCP/OAuth retain their own protocol boundaries
and explicit mappings; ordinary HTTP classification does not automatically qualify them.

### D6 — Preserve business and operation guarantees

Typing/failure corrections must preserve authorization, aggregate ownership, secret redaction, audit atomicity,
transaction boundaries, no-op/idempotency, concurrent-writer defenses, recovery and post-commit outcomes. Preserve
the approved Agent issuance committed-result/warning exception rather than converting committed work into a generic
failure. Synchronous secret-bearing operations remain non-serializable; broader coverage does not authorize
routing raw secrets through message buses.

Apply the pre-v1 current-contract-only policy in ADR 0011: update owned callers/tests/docs directly, without
compatibility aliases, legacy nullable modes, historical readers or migration/backfill paths. Describe breaking
consumer obligations and release classification; this EPIC selects no version and authorizes no release.
