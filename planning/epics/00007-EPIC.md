# Adopt Current Fight Common Contracts

## Destination

Keep Fight AccessControl on supported Fight Common contracts by removing its use of APIs deprecated in Fight Common
1.2 while preserving existing package behavior and transaction guarantees. Completion is required before the planned
`0.3.0` tag, but this compatibility destination is independent of that release's feature name and remains applicable
if release sequencing changes.

## Decisions so far

- The boundary covers production code, tests, configuration, and current consumer guidance. Historical planning
  records remain unchanged as durable evidence of earlier decisions.
- The verified initial inventory identifies `Fight\Common\Application\Repository\UnitOfWork` as the only deprecated
  Fight Common 1.2 API currently used by the maintained package surface.
- Public constructor dependencies may move to `TransactionalUnitOfWork` as a documented pre-1.0 compatibility change.
  No dual-interface bridge will preserve a dependency on the deprecated contract.
- Migration must wrap each complete atomic operation with `commitTransactional()` rather than treating the change as
  a type rename, preserving rollback, post-commit publication, failure rethrow, and request-scoped behavior.
- Acceptance requires a one-time verified inventory against Fight Common 1.2 deprecations. This epic does not add a
  permanent deprecation scanner or quality-gate check.
