# Agent Profile Tools and Name Management

## Destination

Enable an authenticated Agent to read its own minimal profile and change its own name through two protected MCP
self-service tools, while providing one generic package name-update use case that consumer entry points may
independently authorize for self-service or administration. This is a package-owned Domain/Application capability,
not an administrator endpoint, consumer MCP route, or permission to deploy. The behavior is settled by
[WF-024](../wayfinder/tickets/WF-024-self-service-agent-profile-contract.md), with self-service targeting from
[WF-023](../wayfinder/tickets/WF-023-self-service-agent-target.md) and the separate Agent-aware tool authorization
contract in [WF-008](../wayfinder/tickets/WF-008-agent-aware-mcp-authorization-contract.md) /
[EPIC-00005](00005-EPIC.md).

## Accepted behavior

- Each tool takes its target Agent ID **only** from the authenticated Agent principal. Neither tool accepts a
  caller-supplied target ID. WF-008's conjunctive Permission checks, discovery/invocation concealment, and
  request-local freshness apply; the profile capability does not create a second authorization mechanism.
- The profile read performs a fresh lookup and exposes only structured `{agent_id, name}` through Common's
  standard output with matching derived JSON text, not a separately authored success sentence. It does not return
  the administrative `AgentView`, credential information, or Permissions.
- Manage separate `ADMIN_SAFE` Permissions `AGENT_PROFILE_READ` and `AGENT_PROFILE_UPDATE` without automatic grants.
  Each consumer generates their two stable IDs **once** via Fight Common `Uuid::comb()` and fixes them in its
  managed-policy seed/migration; reconciliation must not regenerate them. The package does not prescribe fixed IDs
  or perform consumer rollout.
- Generic package `UpdateAgent` changes only the name. Its typed initiating User-or-Agent identity and the
  name-changed fact record provenance, not authorization; consumers protect **every** entry point dispatching this
  command, including direct bus calls. The MCP updater supplies the authenticated Agent as both initiator and target;
  an authorized administrative caller may supply its authenticated initiator and chosen target through a separate
  consumer entry point, not a package-provided administrator API.
- Reuse `AgentName::fromString()` (trim, reject empty or longer than 120 characters); no uniqueness restriction,
  expected old name, or name revision. Last committed name wins. At the write boundary the current target must be
  `ACTIVE`, and a rename must not overwrite credentials or Permission assignments or restore revoked authority.
  Normalized unchanged input succeeds with no write, `updatedAt` change, or success event. A real name change commits
  atomically before its name-changed fact is published.
- A successful update acknowledges exactly `{agent_id, name}` from the command's target and normalized input
  **after successful synchronous void dispatch**, without a compensating read or handler/bus return. Real changes
  and no-ops have the same acknowledgement, with Common's matching derived JSON text and no `changed` field or
  separate changed/no-op sentence. This describes the successful request, not the latest name after competing
  writes. Invalid names reject with no write or event; missing/revoked current targets
  are generically unavailable with no write. Pre-commit failure rolls back, while post-commit event publication
  failure reports failure without claiming rollback or guaranteed delivery. Sanitize tool errors, preserving WF-008's
  pre-execution unknown/unavailable equivalence and ordinary command failure-event/rethrow behavior.

## Acceptance boundary and exclusions

Use meaningful unit tests for each new class under the package's exact production-statement coverage gate. Add
only a few focused package composition/integration checks where unit tests cannot prove the target binding,
name-only concurrency/authority preservation or commit/publication boundary. Reuse WF-008 authorization evidence;
do not create a duplicate exhaustive discovery/retry suite. Run the full local implementation gate. Controlled
package tests do not qualify a real consumer persistence adapter, scanner, MCP process or security entry point.

Consumers own transport authentication and OAuth-to-Agent mapping, route selection, exposed-tool selection,
authorization for generic command dispatch, managed-Permission seeding and grants, actual persistence and race
qualification, runtime composition, TLS, limits, deployment and adoption. OAuth scopes are not Agent Permissions.
Credential issuance, rotation, revocation, Permission mutation, ownership changes and raw-secret output through
these tools are excluded. A separate administrator API, production Adapter layer, and a release/version commitment
are not part of this EPIC. [EPIC-00005](00005-EPIC.md) retains the reusable authorization mechanism and its
conformance; this EPIC owns only profile behavior and binding these two tools to it.

## Dependency and planning handoff

A compatible, published and installable Fight Common Tool surface is an external **implementation** prerequisite
for the MCP declarations, availability integration and wire behavior. The installed v1.2.0 does not provide it;
inspect its actual public signatures and supported attribute target before implementation, as in
[TASK-00035](../tasks/00035-TASK.md). This does not reopen settled behavior or imply that a generic name-only
Domain/Application use case itself needs Common's Tool API. Decompose requirements and implementation dependencies
separately; neither invent Tool signatures nor block all planning on their absence.
