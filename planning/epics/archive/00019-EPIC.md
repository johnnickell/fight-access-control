# Pre-v1 documentation and developer tooling

## Destination

Make Fight AccessControl easier to adopt and maintain before v1: a concise README, a polished consumer documentation site, a faster and more reliable quality gate, and simpler maintainer tools. Preserve product behavior and verification. John approved this scope, including the Fight logo and Fight Common as the visual quality benchmark.

## Approved scope and acceptance

- **Consumer documentation ([WF-036](../../wayfinder/tickets/archive/WF-036-documentation-and-publication-boundary.md)).** Ship a short README that leads to installation, first use, capability guides and framework setup. Build one consumer-first MkDocs site from `docs/` using the official Fight logo (the [Inward Port mark](../../../docs/assets/README.md)). Match or improve on [Fight Common's docs](https://johnnickell.github.io/fight-common/) in visual clarity and ease of navigation. Review the rendered home page and representative guides on desktop and mobile, including logo legibility, contrast, readable code examples and a clear path from install to integration.
- **Publication and cleanup.** Validate docs before merge and verify that changes landing on `main` automatically update GitHub Pages. PRs and `develop` do not deploy. Surface failures without replacing the last successful site. Preserve the README release panel and link to tagged docs for version-specific guidance. Keep contributor standards, release procedures, planning and detailed evidence out of the published site. Move current material to its owning guides, repair inbound links, and remove superseded notes and `CONTEXT.historical.md` from the working tree. Preserve historical evidence in Git with commit-pinned links where needed, not a new archive.
- **Quality gate ([WF-037](../../wayfinder/tickets/archive/WF-037-quality-gate-speed-and-reliability.md)).** Investigate stale planning views against the tested revisions and profile coverage-enabled PHPUnit first. Compare matched before/after runs; a 15% lower median shared-gate time is a provisional target, not a release gate. Repair timing-sensitive setup where it retains equivalent proof. No test is preapproved for deletion; preserve unique behavior checks, exact statement coverage, Unit-only line coverage and shipped OpenAPI coverage.
- **Static proof ([WF-038](../../wayfinder/tickets/archive/WF-038-static-type-contract-proof.md)).** Move all 52 fixture cases and their manifest to `etc/phpstan/type-contracts/`, outside PHPUnit discovery, ordinary PHPStan inputs and Composer autoloading. Preserve per-file behavior and exact diagnostics in the move. Batch only if separate qualification proves equivalent results and measurable savings.
- **Maintainer tools ([WF-039](../../wayfinder/tickets/archive/WF-039-host-and-composer-tooling-split.md)).** Keep `bin/` host-facing and leave lifecycle, worktree selection and build-cache orchestration on the host. Use Docker for host-facing `bin/` tooling; `scripts/` entrypoints do not require Docker and may use Composer. Preserve offline checks in the prepared runtime. Inventory and eliminate repository-owned Python tooling except for the [approved MkDocs consumer docs and GitHub Pages pipeline](../../wayfinder/tickets/archive/WF-039-host-and-composer-tooling-split.md#approved-exception--consumer-docs-and-pages). The three maintained diagram generators are outside that exception and use PHP. Start with the contract inventory, then the coverage checker and, after the fixture move, the static runner. Use dev-only Composer autoloading without a new console dependency. Focused wrappers and the shared gate use the same PHP entrypoints without nested Docker or duplicate preparation. Verify CLI and failure behavior, worktree selection and existing gate proof.
- **Common helpers ([WF-040](../../wayfinder/tickets/archive/WF-040-prefer-common-domain-helpers.md)).** Start with the 12 equivalent production calls to Common v1.5.1's `email()` helper. Also adopt `string()`, `mb_string()`, `array_list()` and `hash_set()` where equivalent. For typed collections, pass the element class as the second argument and verify PHPStan inference as well as runtime behavior. Record the preference and exceptions in the local PHP standard without a blanket lint rule. Leave non-equivalent factories unchanged.

## Boundaries

No package API or persistence changes, framework scope expansion, changes to Fight Common, branch or release policy changes, or weaker verification. No selected release version or authority to tag, release, merge or deploy is implied by this planning approval. GitHub Pages settings and actual publication are later delivery evidence, not facts established here.
