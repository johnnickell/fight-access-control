# Agent HMAC Authentication and Direct Authority

## Destination

Deliver portable machine-to-machine authentication for one Agent identity: a signed request proves the current
HMAC credential, produces a safe immutable Agent identity with its directly assigned Permissions, and fails closed
without exposing credentials or replay information. Consumer applications retain their HTTP, persistence, keys,
logging, and authorization-policy choices.

## Decisions so far

- Agent HMAC v1 has one active credential, a five-minute past-only timestamp window, and atomic nonce consumption
  after successful request and signature validation.
- Agents use duplicate-free direct Permission assignments, with a separate assignment revision and the existing
  Permission-reference integrity fence.
- Each Agent has a required, non-unique operator-facing name for safe administrative identification; it is not
  credential material or authentication authority.
- Agent authentication returns a distinct request-scoped principal; safe diagnostic classification and correlation
  identifiers preserve operational diagnosis without exposing secret request material.
- Consumer applications map requests into the portable input, decide authorization policy and denial responses,
  and supply persistence, encryption keys, logging, metrics, and runtime composition.
